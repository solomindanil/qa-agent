# Outcome completion — opt-in local qualification

Three journeys: applicable instructions, selected quantity, persistence beyond success copy. The [first-trial cases](cases.md) are frozen for the recorded actor runs; [visible-content extension](cases-visible-content.md) defines the later local regression controls. A tiny owned loopback target, not a new product runner/verdict/storage system.

Commands from root after source restoration, using existing Playwright/Chromium:
If this isolated checkout has no dependencies, set `QA_PLAYWRIGHT_MODULE` to the absolute existing Playwright `index.mjs` path; no implicit install or sibling lookup occurs. That is warm dependency reuse, not cold qualification.

```sh
node --test evals/outcome-completion/fixture.test.mjs
node --test evals/outcome-completion/browser.test.mjs
node evals/outcome-completion/run.mjs
```

Launcher prints a random loopback URL; SIGINT/SIGTERM closes it. State lasts only for that instance. No installs or external fallback. Browser/setup errors are blockers, not product defects. Root npm test remains packaging-only; these controls are opt-in.

First actor receives cases and supplied URL only, proposes design and waits for AQA review before execution. Preserve original design, corrections, actual observations and help separately. Record source/host/model where observable, tools, capture interval, duration/cost limitations and complete G/Q/P denominator. Four fresh-context samples are planned; one sample per variant is not statistical proof.

Reviewer key and control source exist on shared filesystem: open-context, not blind. Controller does not supply them to the actor. Reports are local caller-authored/unattested, no managed attachments.

Save note models only success-copy versus persisted state, not AI tool calling or artifact delivery. Controls cannot close a real product case. W1 live acceptance requires a separately authorized unfinished case under its existing owner/runtime.
