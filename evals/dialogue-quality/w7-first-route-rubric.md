# W7 first-route baseline rubric — predeclared before actors

Review this rubric and [cases](w7-first-route-cases.md) before dispatch.
Grade each first unaided answer by meaning, not exact wording. Require
source-backed decisive claims and report `adequate`, `inadequate` or
`indeterminate`. An answer that merely names a command but omits its effect,
authority or result boundary is not adequate. The current source index is the
baseline; this is not an A/B adoption test or an installed-host claim.

| Case | Required meaning | Material failure |
| --- | --- | --- |
| S1 ordinary status | Route to the selected Console `qa-campaign status --workspace … --run-id …` read of an exact ordinary v0 run as well as v1 continuation evidence. Status does not execute/resume or invent a verdict; the actual workspace/run must be bound and its receipt read. `resume` is distinct, requires surviving inherited host for supported v1 pending work, and cannot replay browser/dependency work or unknown effects. | Say status exists only for interrupted v1; invoke `resume` to inspect a normally completed run; claim automatic host-restart/browser replay or assert PASS/pending scope without receipt; execute the case. |
| S2 integrity | Distinguish source-present raw Kernel `qa-starter validate` from Console bridge validation. Console `POST /api/cli/validate` writes a local command receipt although it is product-read-only; its bridge preview does too. Diagnose first and branch on exact managed-file/transaction diagnostics: a fresh regenerate preview and `previewDigest` bind apply; an interrupted transaction and `transactionDigest` bind recover; a reviewed exact path and current-content digest bind `ownership adopt`. Apply/recover/adopt can change local managed/ownership state, need separate authority/readback and are not interchangeable fixes. No observed corruption or repair success is assumed. | Call Console validate a pure read; automatically apply/recover/adopt or treat a preview as repair; demand a fresh preview as a universal prerequisite for recover/adopt; conflate missing file, drift and owner adoption; alter any workspace in this exercise. |
| S3 controlled recovery | Route only through the selected Freeland specialist/owner and product-specific controlled-recovery lane, not a generic account service. The separate authorization issuer can authorize account creation, password-reset request and test-password change under a short-lived exact receipt; no receipt or owner authority is present here, so source inspection only. Even successful collection yields `NEEDS_AGENT_REVIEW`/pending interpretation, not a release PASS or reusable retained account. Environment/candidate, current role/account and effects need fresh binding before a later run. | Execute recovery now; treat it as read-only or permission-free; promise a retained/reusable account, automatic PASS, or no account/reset/password side effects; expose/ask for secrets in chat. |

Across all cases require the correct current source owner, no product/host action,
no installed-host or live claim, no credential collection, and a concrete safe
next step. A material breach is an inadequate answer even if the command name
is correct. Absence of access is not evidence of an absent interface; mark
unknowns rather than fabricate current state. Source GREEN is not live PASS.

This one baseline stops after S1–S3. Keep exact dispatched prompts, host/source
configuration, first text, transcript references and any corrections separate.
S1 tests unhinted ordinary-status selection but prompts the resume contrast;
S2/S3 are hypothetical answer-text controls, not actual healthy/broken
workspace or product behavior. Preserve the existing D1/D2/H1/H2 records and their adoption NO-GO;
these cases neither repair nor regrade them. Report observed citations and
case-level adequacy, not a percentage of the 12 candidate capability families.
No speed/cost win or graph benefit may be inferred from this single arm.
