# Agent entrypoint — shared by Codex and Claude

This repository is the source workspace for QA-agent. Use the [manifest](sources/manifest.v1.json) for delivered source selection, the [current checkpoint](docs/qualification/current.md) for present status, and the selected product owner for an existing campaign's frozen runtime. None of those alone grants permission to act on a product. See the [architecture](docs/architecture.md) and [documentation index](docs/README.md) for navigation.

## Before work

1. Resolve this normal Git root. Read the manifest and [assembly boundary](docs/qualification/assembly.md); for source-dependent work run `npm run sources:verify`. If components are absent, `sources:restore` uses local bundles and refuses conflicting or dirty destinations. Root tests prove packaging, not product QA.
2. Resolve the product and its owner in [product routing](products/README.md). If no specialist is selected, use root [qa-check](skills/qa-check/SKILL.md) once for routing. Read the selected complete source skill and required references through the [skills index](skills/README.md). Run child-relative commands from that child, not an old working directory.
3. Verify the actual component checkout, product environment/candidate, capabilities and action-time authority. A source pin, copied policy, old approval, account, receipt or saved path does not authorize execution. Check other active campaigns before writing shared state; keep one owner per campaign and do not silently migrate or re-register it.

## Working rules

- Use one normal clone of verified public `develop` as the development entry; preserve dirty old clones and product-owner checkpoints. The [global plan §6](docs/superpowers/plans/2026-10-05-universal-qa-product-plan.md#6-общий-цикл-каждой-реализации) governs one cycle: applicable accepted design for changed contracts/semantics → implementation and affected checks → self-review → one author-distinct AQA → PR and own delivery evidence. Actual Sol 6.1 authors code/checks; actual Astra decides new architecture/API/schema/lifecycle/dependencies and reviews independently. The same reviewer checks affected repairs; no separate full source/package/docs acceptance stages or unchanged qualification replay. Retain FIRST logs, tested source identity and unknown scope, not a mandatory per-slice qualification/hash-ledger ceremony. Independent preparation may overlap CI in isolation; common writes/merges remain serial, with one CI observer and meaningful updates only. Prioritize ordinary QA→saved report→UI→fresh continuation and V01; a failed feature stays unavailable, never “flaky PASS” or quarantined to bypass acceptance.
- The agent owns grounded expectations, risk-based design, investigation, diagnosis and the reported QA conclusion. The selected tools own identity and effect guards, execution, persisted evidence and verdict boundaries. Do not create a second runner, manually mark unsupported scope PASS, or treat a source self-test as product acceptance.
- Preserve the denominator: distinguish verified, failed, blocked and unassessed checks. A graph guides dependencies but does not prove a test ran or identify a live deployment. Graph and oracle changes require the owning review/publication path and relevant requalification.
- Ask for specific missing human input only where it blocks a dependent lane; continue independent permitted work. Record attempted methods, missing input and a resume checkpoint. On return, recheck current product, account, candidate and unknown effects before retry. Never request passwords, OTPs or payment secrets in a report.
- Use the product-selected tracker and integration, not a universal default. Report-only QA makes no tracker writes. An authorized write requires the selected product's confirmation, dedupe, target/state contract and persisted readback; reconcile an unknown outcome before retry. The [Buzz contract](docs/communication/buzz.md) applies only when preparing or sending authorized Buzz coordination.
- When the selected integration is Nuanu Flow, use its available official host plugin and read its current skill/catalog first. Do not hand-edit a managed Starter graph or promote a caller-authored observation to sealed evidence.
- Protect credentials, sessions, private provider/account data, traces, active graphs, outboxes and managed registrations outside tracked delivery. `.local/` is ignored, not a security boundary. Use distinct private product/run roots; never transfer product-specific business rules, fixtures or financial authority to another product.

## Component and effect boundaries

Console and Kernel form the general Starter lane; Freeland retains its specialized graph, campaign and verdict tools. Read the [architecture](docs/architecture.md) and selected specialist before commands. An existing campaign may retain an older frozen runtime even when the manifest selects newer source. The inactive reporting reference is not a substitute for the selected Kernel. Keep source pins frozen during a campaign; changes to tests, oracles or graph inputs need their owning identity refresh.

The root `npm test` checks packaging. A component's default `npm test` may start browser or product work. No implicit live fallback, dependency/skill/plugin installation, watcher, delivery, payment, cloud setup, deployment or migration is authorized by this entrypoint. Product Freeland remains read-only here: no push, deployment or migration. Use explicit current checkout, workspace and state paths; never import historical machine defaults. The [command record](docs/qualification/commands.md) is historical.

## Resume and historical material

Read the [current checkpoint](docs/qualification/current.md) and [one queue](docs/roadmap/README.md), then the selected product owner. End with exact results, limits and the next bounded action. Dated qualification, evaluation, plan and [reference](references/README.md) material preserves provenance; its former “current,” “next” or “approved” language is not a new instruction. The [local consolidation index](docs/qualification/local-consolidation-20260920.md) distinguishes selected source from inactive candidates. `tools/android-pilot/` remains opt-in experimental source, not a qualified execution lane.
