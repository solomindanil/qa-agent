## Grounded clause recipe

Before product action, keep one compact list/table in existing notes, keyed by the existing target/check. For each material clause retain:

1. Exact source document/section or supplied decision, revision/digest when available, authority and product/version/role applicability. Distinguish requirement, observed baseline, hypothesis and unresolved question; unknown identity remains unknown.
2. Product/environment/build, role/account/object, fixture and preconditions. Repository revision is not observed deployment identity. Non-applicability needs a scoped reason; uncertainty never silently removes an item.
3. The smallest independently promised outcome, action, observation surface, journey point and any source-backed time bound. If an implementation could satisfy the source but contradict a proposed clause, remove that invented extension from the normative expectation and retain it only as a hypothesis. One check may cover several clauses with distinct assertions/witnesses.
4. Evidence that discriminates success from the nearest plausible failure, supported lane, retention and current effect authority. Write acknowledgement does not prove persisted state; HTTP 200 does not prove semantic content.
5. After observation, exact evidence ID or original artifact/check/attempt and relevant content, observation time and object/session identity, then supported/contradicted/blocked/unassessed/unresolved reasoning and bounded next action. These are note labels, not new owner enum values.

Preserve the complete expected outcome verbatim where required. Summarize supported and unsupported parts in existing observation/review text and limitations using only legal owner classifications/results. A compound check cannot pass because one clause matches. Missing evidence is not failure; unknown/conflicting normative expectations are not product bugs. A contradiction still requires oracle, fixture, locator/readiness and environment diagnosis before a confirmed-bug claim.

Mappings and item statuses are agent-authored prose, not machine-enforced facts. Strict plan schema and single aggregate observation result stay unchanged. Owner validation cannot certify decomposition or completeness; independent semantic review does. Do not represent clause counts as owner-computed managed coverage.

Do not choose a conflicting source by file date, current UI or convenience. Keep both sources, scopes and exact disagreement. Only a documented authority/applicability rule can resolve it; otherwise preserve unresolved expectation, ask one precise question or investigate authorized sources, and continue independent permitted work. Never fabricate a resolved oracle to satisfy a writer. Local labelled notes and blocker remain until the existing reviewed publication/approval path legitimately resolves the expectation.

Readback proves storage/binding claims, not observation truth or reasoning sufficiency. A current local binding is not deployment attestation. Graph mapping is not execution; review never automatically changes receipt, managed coverage or release verdict.

### Persistence and delayed outcomes

Separate acknowledgement, interim state and promised later state. Freeze source-backed deadline/window before observation; do not tune until green. Use existing `eventual`/`absence_window` only where supported, preserving actual elapsed time/sample count and sampling limitation. Otherwise use an authorized observation lane or retain the capability gap; no scheduler/controller is proposed.

For persistence use reload/return or the requirement's authoritative read, with the same relevant object/account and candidate. For async outcomes retain terminal content/status and elapsed time linked to the original action/object. Early absence within the window is not final failure; timeout without authoritative deadline supports only bounded observation, not an invented defect. Reconcile unknown original effects before retry; no replacement action for cleaner evidence.
