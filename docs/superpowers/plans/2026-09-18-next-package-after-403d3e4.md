**Принцип порядка:** сначала то, что теряет смысл со временем (RED на текущей сборке), затем то, что разблокирует остальное (принятие результатов, фикстуры), потоки с разными владельцами идут параллельно. Один владелец общей записи: интеграцию source ведёт основной агент Codex, Claude выполняет read-only QA продукта и независимое ревью.

## Порядок на сегодня

1. Поток A запускается сразу: read-only, без разрешений, теряет смысл после деплоя фиксов.
2. Поток B начинается, как только есть сессия Flow; Buzz после подтверждения текста.
3. Данил решает по потоку C: кто ведёт интеграцию и «да» на коммиты.
4. Claude готовит текст запроса фикстур для потока D.

## Правила, которые не меняются

- Продуктовый репозиторий read-only; production только для сравнения; агент не платит и не вводит реквизиты.
- Ожидание не меняется ради зелёного теста; устаревшее после законной смены продукта ожидание пересматривается по тикету.
- Принятие source не мигрирует кампании и installed skills; исторические артефакты не удаляются.
- Каждое отклонение воспроизводится дважды и относится к одному из трёх классов: дефект продукта, расхождение каталога, проблема харнеса.
- Ответ «готово» проверяется фактом: текущие аккаунт, среда, сборка и реальная готовность.
