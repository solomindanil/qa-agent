## 3. Правила

1. **Одна очередь:** обязательства создают база и принятые поправки R1. Новая идея — строка поправки с ID среза, новый plan-файл не заводится.
2. **Один автор общих записей — Codex:** manifest, candidates, components, skills, `AGENTS.md`, `current.md`, roadmap, plans, `package.json`, tests, tools, CI, коммиты, push. Автор не ревьюит себя. Правки Claude в харнесе (например `aa1d0ae`, oracle spec) остаются в `.local`, пока Codex их не примет.
3. **Одобрения для любого агента:** контакт со стендом одобряется на конкретный прогон (команда, sha сборки, лимит времени и стоимости); запись в tracker и Buzz — на пакет с точным текстом; установка скиллов — отдельным шагом; деньги агент не трогает никогда.
4. **Сделано:** строка §9 выполнена целиком, включая отрицательный и исправный контроли; exact reviewed bytes в bundle → manifest → cold restore и verify → зелёный CI → свежий неавторский потребитель → запись по составу базы §9 (строка «Для каждого среза сохранять…») → чекбокс в базе со ссылкой.
5. **Продуктовое прерывание:** park-note в статус-блоке; QA на замороженном runtime; правки харнеса только локально до окна интеграции. Close-out дня: отклонения → `pending-tickets.md`, реестр статусов → очередь нагрузки P1 (только как исторические unattested-записи), уроки → строки поправок. При деплое фиксов: повтор проб на замороженном runtime и GREEN тех же oracle.
6. **Evidence:** read-only и повторяемые отклонения воспроизводятся дважды; денежные, изменяющие и с неизвестным эффектом сверяются по тому же ID операции, а не повторяются. Каждая находка относится к одному классу: продукт, каталог или харнес. Неизвестное не PASS; ожидание не меняется ради зелёного теста.
7. **Ретенция:** агенты ничего не удаляют; владелец вручную удаляет только воспроизводимое (клоны продукта, `node_modules`, трассы).
