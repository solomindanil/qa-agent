# Improvement roadmap

The [iteration and PR-delivery index](../superpowers/plans/2026-09-30-universal-qa-agent-iterations.md) gives the current quality-first order as small independently verifiable steps. It separates unpublished local work, source delivery and runtime/host/product acceptance; publishing the index does not resume the paused implementation. Each new authorized implementation has its own branch, self-review, independent AQA and PR, with exact-base conflict checks and push readback; merge is not automatic.

The [unified QA-agent implementation plan](../superpowers/plans/2026-09-23-unified-qa-agent-implementation-plan.md) remains the requirements ledger, not a competing execution queue. P0–P7 name the durable obligations; W packages and I ordering organize bounded implementation, not new acceptance stages. Its [no-loss comparison](../reviews/2026-09-23-global-plan-reconciliation.md) preserves prior obligations and distinguishes adopted work, open acceptance and owner-deferred work.

Read the [current checkpoint](../qualification/current.md) for delivered-source status and its qualification limits. The iteration index above selects the development order and next gate; older “next” or canonical-plan pointers in the delivered checkpoint are historical for queue ordering, not a route back to the previous queue. Read the [product owner](../../products/README.md) and selected specialist before any product work. A queue item, source pin or local gate does not grant product, tracker, cloud, payment or deployment authority; an existing campaign keeps its frozen runtime.

Historical roadmap snapshots and plans are indexed in the [archive](../archive/README.md). Their dated “current,” “next” and local-path statements preserve provenance, not a competing queue. No full-product coverage or universal reliability claim follows from bounded source gates or evaluations.
