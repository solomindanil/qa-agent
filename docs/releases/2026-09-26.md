# QA-agent stable source release — 26 September 2026

Stable source baseline for tag `qa-agent-2026.09.26`, qualified with Node.js
22.23.1 on Linux and bounded macOS checks. The executable commit is
`70942407e8e007aa9a39a0d6d3933248aaf3d8c8`; the final release adds documentation
and manifest qualification metadata only. Component source bytes, bundles,
lockfiles, guards and executable workflows remain identical to that tested commit.

## Frozen scope

The source base is `2f507fc`, before the unfinished W4 change-scope experiment.
The initial pair was Kernel `a0a20e6` / Console `f75d963`. Hosted Linux
qualification exposed two inode-related failures and six integration timeouts.
The release selects Kernel `ece24e865f7ea37cff32c24c7e3739c9d0059f81` and exact-pin
Console `a8f66792f8053f125bf8ffc758f543f25a2b95a1`. Freeland `0ea2df1` and inactive reporting reference
`10d398d` retain their original bytes. Existing campaigns and installed skills
retain their prior sources; these repairs are confined to the release clone.
Historical and candidate bundles remain inactive unless selected by the manifest.

The Kernel repair keeps the claim-receipt staging descriptor open until publication
and cleanup finish, preventing an unlinked inode from being reused as another
writer's file while it is still treated as owned. The existing substituted-temp
regression failed on Linux before the repair. The restoration test now holds its
removed file open so its different-inode assertion is portable. No assertion is
removed. Six multi-phase integration tests receive explicit budgets: two workspace
cases and one three-variant job case use 30 seconds; three service cases use
180, 120 and 240 seconds respectively. This is test budget calibration, not a
runtime speed improvement or a claim that the old-budget attempts passed.

Use [Getting started](../getting-started.md) and explicit source-skill routing.
The baseline supports the existing bounded local QA workflows; it does not
promise full product coverage, deterministic agent reasoning, Windows/cloud
execution, or automatic adoption of work still under development.

## Isolation

Release work runs in an independent Git clone with its own dependencies, build
outputs and temporary stores. The active QA FREELAND and MagicPay owners retain
the original source checkout, private registries, browser state and frozen
campaign runtimes. No shared working branch or installed skill is switched.
No product, payment, tracker or provider call is part of these release gates.

Runtime CI installs each child's locked dependencies with lifecycle scripts
disabled, builds the pinned pair, uses canonical runner-private state and
re-verifies source integrity after execution. The independent source-safety
workflow remains unchanged. Fixtures are local and synthetic: these gates do
not attest live-product acceptance or the full Console product-facing suite.

## Diagnostic history and limits

The initial pair was tested before the repair. Full Linux run
[36232057727](https://github.com/solomindanil/qa-agent/actions/runs/36232057727)
hit its 60-minute job limit after reporting eight failures; it did not pass.
[Targeted Linux diagnostics](https://github.com/solomindanil/qa-agent/actions/runs/36235165512)
reproduced both inode failures and all six timeouts. The repair retains every
assertion, corrects inode lifetime/fixture assumptions, and explicitly calibrates
six integration budgets. Earlier failures remain failures; the release does not
claim that runtime speed or every scheduling sensitivity was fixed.

The original macOS full Kernel invocation completed in 3,139.31 seconds with
1,786 pass / two timeout failures. Both repeated at their original 10/120-second
budgets. The new Linux full gate and targeted repaired-source macOS checks have
their own attribution; there is no new full macOS Kernel PASS claim.

The first hosted Console run failed two continuation-authority controls because
the runner inherited executable `filter.lfs.*` Git settings. Reproduction used
an owned temporary config. Process-only `GIT_CONFIG_NOSYSTEM=1` and
`GIT_CONFIG_GLOBAL=/dev/null` resolve that environment mismatch without changing
the source guard or host configuration. CI records helper key names, not values.

The original local Console 163-test run had 161 pass, a macOS temporary-path alias
failure and a paired-observation timeout. Canonical TMPDIR resolves the path
reproduction (6/6). An isolated pair passed at 178.99/180 seconds; a later wider
run had 162/163 pass and a 45-second bridge snapshot timeout. A serial pair then
passed in 142.37 seconds with its original 180-second limit. These attempts are
retained; they do not constitute a new full local 163-test PASS. The final hosted
163-test PASS belongs to the repaired exact source pair. The prior built-UI
smoke (HTTP 200, visible synthetic observation, no page errors) belongs to the
original pair and is not relabelled as a new-source UI run.

A cold-clone Freeland run deliberately used `nice -n 10` to reduce local CPU
priority. Its first suite stopped at 735/736: the maxBuffer/process-group test
returned the fail-closed cleanup error instead of the expected output-limit
error; later suites did not execute. The unchanged process-group file then
passed 18/18 at normal priority, followed by the complete normal-priority cold
run passing 3,059/3,059 and source integrity. The earlier isolated release-clone
full offline run also passed 3,059/3,059. No Freeland cleanup guard or source was
changed; a general scheduling-sensitivity fix is not claimed.
