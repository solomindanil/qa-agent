Release preparation is in progress. This record will be finalized only after

## Frozen scope

The source base is `2f507fc`, before the unfinished W4 change-scope experiment.

qualification exposed two inode-related failures and six integration timeouts.
The repaired candidate selects Kernel `ece24e865f7ea37cff32c24c7e3739c9d0059f81` and exact-pin
Console `a8f66792f8053f125bf8ffc758f543f25a2b95a1`. Freeland `0ea2df1` and inactive reporting reference
`10d398d` retain their original bytes. Existing campaigns and installed skills
retain their prior sources; these repairs are confined to the release clone.
Historical and candidate bundles remain inactive unless selected by the manifest.

The Kernel repair keeps the claim-receipt staging descriptor open until publication
and cleanup finish, preventing an unlinked inode from being reused as another
writer's file while it is still treated as owned. The existing substituted-temp
regression failed on Linux before the repair. The restoration test now holds its
removed file open so its different-inode assertion is portable. No assertion is
removed. Six multi-phase integration tests receive explicit budgets: two workspace
cases and one three-variant job case use 30 seconds; three service cases use
180, 120 and 240 seconds respectively. This is test budget calibration, not a
runtime speed improvement or a claim that the old-budget attempts passed.

Use [Getting started](../getting-started.md) and explicit source-skill routing.
The baseline supports the existing bounded local QA workflows; it does not
promise full product coverage, deterministic agent reasoning, Windows/cloud
execution, or automatic adoption of work still under development.

## Isolation

Release work runs in an independent Git clone with its own dependencies, build
outputs and temporary stores. The active QA FREELAND and MagicPay owners retain
the original source checkout, private registries, browser state and frozen
campaign runtimes. No shared working branch or installed skill is switched.
No product, payment, tracker or provider call is part of these release gates.

### Diagnostic attempts retained

The first hosted Console run failed two continuation source-authority controls
because the runner inherited executable `filter.lfs.*` Git settings. This was
reproduced with an owned temporary config. Process-only
`GIT_CONFIG_NOSYSTEM=1 GIT_CONFIG_GLOBAL=/dev/null` makes the unchanged controls
pass; the guard and host configuration remain unchanged. CI records helper key
names without logging values.

The first local 163-test Console run had 161 pass, one macOS temporary-path alias
assertion failure and one paired-observation timeout. Canonical TMPDIR fixes the
path reproduction (6/6 unchanged portability tests). An isolated pair passed in
178.99 seconds of its 180-second budget, but a subsequent wider local run had
162/163 pass and hit its 45-second bridge snapshot limit. These attempts do not
establish that timing sensitivity is fixed. The local full Kernel run completed in 3,139.31 seconds: 43/45 files and
1,786/1,788 tests passed. Both failures were timeouts: atomic V2 registration
republication (10 seconds) and resuming `PUBLISHING` over prior authority
(120 seconds). Both reproduced when selected individually in a serial run with
canonical private TMPDIR and the original budgets. They remain unresolved local
failures; no retry replaces the full-run denominator, no timeout is increased,
and no failing assertion is removed. The serial Console paired-observation test
passed in 142.37 seconds with its original 180-second limit (one selected test,
no skips); this confirms that case, not a new all-green 163-test local run.

The runtime workflow installs locked dependencies with lifecycle scripts
disabled, builds the pinned pair, exercises contract/API/observation/browser
controls and re-verifies source integrity. The complete Kernel test collection is now partitioned into three disjoint
jobs (workspace regeneration, registration service, all remaining files), each
using the normal test command; their union must cover all 45 files / 1,788 tests.
Kernel typecheck/build are covered by runtime-smoke. Existing source-safety CI remains
separate and unchanged. All runtime fixture targets are local and synthetic;
these gates do not attest live-product acceptance.
