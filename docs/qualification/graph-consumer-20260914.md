loopback API. Their common B contains journey J, invariant I, resolved D→J and
resolved C→I. Both keep the same catalog checks and expectations. Treatment alone
receives a reviewed `J --requires--> I` through revision, preview, apply and actual

must be preserved. Necessary digest cascades are not product behavior changes.

Two fresh consumers receive the same named-journey catalog-reuse request. They
read graph/catalog and independently author supported operations/assertions for
existing check IDs and exact oracles. Preparation supplies no executable plan.
Each records its decision before execution, persists the original plan, runs the
existing CLI, diagnoses non-pass evidence, and reads the actual receipt.

The expected mechanism is treatment J→I←C resulting in D+C, while control may
select D with I/C explicitly unassessed for this campaign. Control still has
automated catalog coverage for I: omission is not lack of automation or access.
Useful exploration is allowed. If control also selects C independently, that is
not an agent failure and cannot be relabelled a graph-caused selection difference.

## What improved and what did not

This adds a reproducible evaluation of **agent decision → existing runner → actual
reader**, following a real reviewed knowledge publication. It does not add a
selector, runtime feature, new product test or complete learning loop. The graph
provided an explicit basis for treatment selection; the control found the same
important check from the brief. Calling that an incremental coverage benefit
would be unsupported. The original pair is retained rather than resampled.

Next useful evaluation: a different realistic change with a less-obvious known
dependency, sufficient independent requirements and both relevant/unrelated
checks. Measure selected and actually executed scope, known-regression detection
and cost. Do not suppress sound agent inference or hide requirements to manufacture
an improvement. Freeland source-impact debt, unknown-change fallback and broader
cross-product/host qualification remain separate open work.

## Limits

Prepared registration does not qualify autonomous onboarding. The instruction-
scoped fresh contexts are not security-isolated blind benchmarking. Different
agent-authored assertions can confound detection outcomes and must be inspected.
Here their executable assertions match. Control additionally saw inline historical
manifest annotations while verifying pins after its selection was frozen; no
linked history, fixture/controller or sibling workspace was inspected. This is
an explicit exposure limit, not a claim of perfectly blind benchmarking.
One dependency comparison does not establish universal risk selection, complete
Stage4, all-product coverage, current Claude execution or cloud readiness.
No live product, payment, account, SQL, provider or tracker operation is authorized
or performed by this source-only qualification.
