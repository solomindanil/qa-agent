# Immutable first design

Written before any request to a release origin or any registered-workspace packet was received. This is my independently chosen contract design from the supplied product brief, not an executable graph-bound plan. I will bind separate new plans only after receiving current registrations and will stop for independent design review before campaign execution.

The public integration consumer needs two anonymous read-only GET contracts. Each check deliberately separates transport status, declared media type and JSON content: correct Content-Type alone cannot establish promised content. The OpenAPI check has five assertions and the status check has three, covering all eight material promises. `json_pointer` resolves the literal `/v1/widgets` key using `~1` escaping; it does not inspect an unrelated nested `v1.widgets` object or a textual occurrence elsewhere. Exact scalar equality is justified by the brief's normative wording, including the OpenAPI version string and operation summary.

I use `media_type`, not exact Content-Type header equality, to permit valid parameters and case variation. JSON assertions target only promised fields, not whole objects or serialized body text, so object ordering and undocumented properties do not create false failures. The new selected assertions enforce JSON parsing; a status/media response with wrong, missing or incorrectly typed content must not pass the relevant field assertion. This design does not add full OpenAPI-schema validity, duplicate-member detection, performance thresholds, caching requirements, `/v1/widgets` endpoint behavior, or other unpromised requirements.

Scope denominator is four known surfaces: two selected API contracts, `/docs/` unassessed because rendered documentation is explicitly outside the request, and `/member/audit` blocked because member identity is absent and authenticated work is unauthorized. Neither gap can be inferred from API success. Source verification and plan validation are harness evidence only, not product acceptance. Repeated oracle failures remain the runner's `needs_review`/`INCONCLUSIVE` until diagnosed; I will preserve original attempts rather than rewrite receipts or automatically rerun campaigns.
