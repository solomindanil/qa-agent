## Независимый разбор проблем

- Wallet RU действительно показывает `Insufficient available balance to place a hold.`
  на обеих попытках. Это соответствует ранее зафиксированному FREEL-424;
  свежий read через Nuanu Flow вернул403, поэтому текущий статус тикета не подтверждён.
- 3 VPN-проверки требуют старый Karing/тарифный UI при существующем активном VELVET.
- 3 screenshot-проверки магазина ищут старый текст вместо «Во имя свободы».
- Tokenless reset-тест требует expired, хотя исправленный контракт FREEL-439
  отдельно классифицирует неподтверждённую ссылку как unavailable. Доказательство
  исправления настоящей свежей ссылки не заменяется этим отрицательным кейсом.
- 6 mobile failures связаны с устаревшими признаками готовности маршрута:
  2 проверки не учитывают стрелку в CTA, 4 ищут английское имя Freeman в RU UI.
  Проверки после этих остановок не выполнены, все6 остаются failed.
- На support/numbers390px подтверждено визуальное наложение «Пополнить» на
  область «Назад» на11px. Влияние на фактический клик не проверено; новый тикет
  без проверки дублей не создавался.
- В38 независимых runtime-вложениях зарегистрирован HTTP429 session-surface.
  Остальных записанных HTTP≥400 и JS-errors в этом route-census нет. Его5
  параллельных workers могли повлиять на лимит60/5мин; одиночное воспроизведение
  пока не выполнено. Это одна повторяющаяся находка, не38 разных дефектов.

Итого14 unexpected failures:13 расхождений QA-ожиданий с текущим контрактом и
1 воспроизведённый дефект локализации. Объяснение падения не превращает его в
PASS: нужен исправленный QA-корпус, повторная проверка и новая generation.
Снимки Wallet на mobile/tablet ещё содержат loading; они не доказывают вечную
загрузку. Текст eSIM «Истекает Недоступно» соответствует fallback пустой или
невалидной даты; фактическое API-значение даты в этих артефактах неизвестно.

Известные expected failures тоже не исчезли: навигационный active-state,
Freeman390px, PWA stale-shell и SEO. Обе мобильные join-проверки остановились

Все5 обязательных safety-spine controls прошли с первой попытки. Причина

## Покрытие и честные границы

Карта учитывает 17 доменов и 8 критических зависимых цепочек. Реально выполнены
web auth/session/access gates, основные продуктовые страницы, варианты оплаты
до подтверждения, кошелёк, каталог карт/eSIM/номеров/VPN, навигация, inbox/mail/
support/referrals/Freeman, локализация, клавиатура, responsive/SEO/PWA/TMA-web
проверки в пределах конкретных assertions. Это не все состояния каждой услуги.

Нельзя считать пройденными только по этому green-подмножеству:

- новые списания/выдачу продукта/возвраты/settlement и полный concurrent SQL;
- недоступные fixture-ветки IDOR, истории карты, нескольких номеров/источников
  баланса; pool-role нельзя назначить произвольному аккаунту ради зелёного результата;
- native Telegram/Stars, установка eSIM и передача трафика, получение SMS,
  работа внешнего VPN-клиента и реальная доставка сторонних провайдеров;
- Passport onboarding/handoff: даже GET списка может вызвать provider POST при
  cache miss. Это также возможно при штатном открытии «Мои сервисы», но факт
  создания провайдерской записи текущими артефактами не установлен;
- production schema/cutover/worker cycles. API readiness не заменяет эти проверки.

Граф действительно использован для полного выбора: 254 из320 changed-file records
не имеют mapping; full mode не делает необоснованного сужения. Но176 diagnostics
coverage debt остались. Статические74/136 mapped requirements и266 тестов не
