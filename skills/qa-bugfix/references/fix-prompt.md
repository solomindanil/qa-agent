# Fix prompt template

Generated by `qa-bugfix` — one prompt per evidenced bug cluster. Fill from the
selected product pack and issue evidence; do not invent omitted facts or authority.

```markdown

Registered checkout: <exact supplied registration locator; otherwise unresolved,
resolve before edits and keep the workflow checkout-neutral>.
Tracker: <provider, workspace/project>.
Tickets: <exact issue IDs and supplied links; no invented links>.
Observed buggy environment/candidate: <identity from the evidence>.
State contract: <literal state names mapped to implementation/QA roles, or unknown>.
Current allowed actions: <from the scoped request; preparation is not execution>.

You are fixing <N> confirmed bug(s) for this product (<stack, if known>).
Scope: exactly these bugs; minimal diff, no unrelated refactoring.
Apply this work only in the intended product checkout under its current
instructions and task authority. This artifact grants no additional permissions.

no credentials>

<!-- Repeat per bug; explain the shared cause or keep independent risks separate. -->

## Acceptance criteria

- [ ] <original scenario succeeds under the original preconditions>
- [ ] <the incorrect effect is absent; specify what is actually observed>
- [ ] <related behavior from the product map/contract remains correct>
- [ ] Relevant project checks pass; list what was run and what was not
- [ ] Existing regression fixtures/assertions are checked against the original
      scenario. Unexpected expected-failure PASS is a signal for investigation,
      not sufficient fix evidence. Do not weaken assertions to get green.

## Implementation handoff / QA acceptance

- **Developer completion:** return changed scope, exact implementation candidate,
  tests/results and unresolved checks. Use <pack-defined implementation handoff
  state, only if known and authorized>; otherwise return evidence without a
  tracker transition.
- **QA acceptance:** <pack-defined QA-qualified state, if known> requires fresh
  deployed original-scenario evidence and authorized QA transition/readback.
  Do not use this state as the developer-completion shortcut. Local tests and
  implementation completion are not deployed QA acceptance.
- **Tracker authority:** <selected project/tracker and current allowed writes,
  or prepare-only/no writes>. Connector availability alone grants no writes.

## Recommended workflow

- Inspect relevant source and reproduce with authorized test data before editing.
- Keep the fix focused; run applicable typecheck/lint/tests and adjacent checks.
- Use browser tools or an independent reviewer when available and useful.
- If a necessary product decision or capability is missing, report that specific
  gap and continue independent safe work; do not invent the contract or access.
- Return implementation evidence to QA; do not assert deployed verification
  unless that separate authorized verification actually occurred.
- Before delivering, reconcile all product/issue/state/environment references
  with the original pack/snapshot. Keep exact names, not synonyms or values from
  another case. An unresolved target remains a draft, not a transition request.
```
