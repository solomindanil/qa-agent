# Sati 3.0.1 (15) iPhone-proxy deep release campaign

## Release verdict

**NO-GO for production on 2026-09-01.**

The exact TestFlight candidate is `3.0.1 (15)`, bundle
`com.satiuniversity.sati`. The deepest safe computer-only campaign found two
critical release defects and several high-severity configuration, acquisition,
privacy, and push risks. The current build must not be promoted as tested for
iPhone: the Mac portrait proxy covers React layout and anonymous logic, but it
cannot reproduce iPhone safe areas, touch, software keyboard, suspension,
permissions, APNs, StoreKit, HealthKit, or a signed-in product journey.

The Mac-only black-screen and fullscreen defects remain real because TestFlight
currently exposes that compatibility path, but they are no longer treated as
evidence that a physical iPhone would fail. The broader release-scope defect is
that an iPhone-only product declares iPad support and landscape layouts.

## Evidence boundary

- Distribution: exact TestFlight candidate `3.0.1 (15)` released 2026-09-01.
- Runtime: macOS 26.2 Apple Silicon running the TestFlight iOS-on-Mac build.
- Portrait proxy: outer Sati window approximately `516 x 893` pixels including
  the macOS title bar. This resembles compact portrait, but the React client
  rectangle and iPhone safe-area insets cannot be read back exactly.
- Authentication: synthetic invalid login only. No account was created and no
  Apple, Google, or VK provider login was submitted.
- External writes: no purchase, subscription, reset email, HealthKit write,
  notification permission, profile/community mutation, or production data
  mutation was performed.
- Public-network audit: intentional probes were GET, HEAD, and OPTIONS without a
  cookie jar. One temporary browser load of the privacy page may have generated
  one automatic first-party `page_hit` from the page's own tracker; no form or
  personal data was supplied.

## Confirmed release blockers

| Finding | Severity | Result and impact |
| --- | --- | --- |
| F-007 | Critical | Product is iPhone-only, but native `UIDeviceFamily=[1,2]`, Expo `supportsTablet=true`, and iPad landscape are enabled. Untested iPad/Mac surfaces are published. |
| F-009 | Critical | Complete GraphQL sign-in bodies, including plaintext synthetic passwords, persist in the sandboxed CFNetwork disk cache after quit/relaunch. |
| F-002 | High | Packaged Expo update request has no channel header and receives HTTP 400 `channel-name: Required`; OTA checks cannot obtain an update. |
| F-010 | High | The production share/acquisition link is branded `Cielo`, targets App Store ID `1513177968`, and that iOS listing returns 404. |
| F-011 | High | Root privacy manifest declares zero collected-data types while app-owned PostHog capture/identify code is embedded; App Store labels/runtime behavior require readback. |
| F-012 | High | Signed APNs entitlement is production while packaged OneSignal mode is development; real device push remains unproved. |

These are sufficient for NO-GO without relying on the Mac-only layout defects.

## Additional confirmed defects and risks

- F-005: all five camera, microphone, photo-library, and HealthKit usage
  descriptions are English with no app-owned `InfoPlist.strings`, despite the
  observed Russian UI.
- F-006: Expo asset manifest declares conflicting hashes for the same clear and
  close icon destinations.
- F-008: Expo Constants can report build 14 inside signed build 15.
- F-013: release bundle retains Expo development-client configuration, an
  `exp+sati` scheme, local-network access, and dev-launcher/menu symbols. A safe
  runtime probe did not prove the dev UI reachable.
- F-014: public legal pages contain template residue and automatically execute a
  first-party page-hit tracker; legal adequacy needs owner review.
- F-015: email login lacks obvious local format/length validation.
- `/gql` GET/HEAD returns 405 without an `Allow` header; low-severity API error
  handling issue.
- OneSignal Location is linked without an `NSLocation*` usage string. No
  app-level location request was proved, so this remains conditional.
- No Associated Domains entitlement is present. Universal-link behavior is not
  available unless the product intentionally uses only custom schemes/web.
- Expo Updates has no client-side code-signing certificate/metadata; TLS exists,
  but client-enforced end-to-end OTA signing was not found.

## What passed

- Anonymous onboarding is visually usable in a compact portrait-shaped Mac
  window once the cold-render workaround is applied.
- Intro play/pause/skip and voice choice work, and background switching did not
  duplicate audio in the proxy.
- Long Unicode form input remains responsive and masked where expected.
- Unknown and malformed custom URLs fail safely, and ten repeated launches keep
  a single process/window.
- Authentication error wording avoids obvious account enumeration.
- ATS arbitrary loads are disabled; no first-party cleartext origin was found.
- App/extension signing, app group, HealthKit and Apple Sign-In capabilities are
  structurally coherent; `get-task-allow=false` and the main executable is
  encrypted.
- Bundled splash, Hermes program, frameworks, fonts, images, and media inventory
  are present; the initial black screen is not explained by a missing splash or
  missing main bundle.

## Fix and retest order

1. Remove unintended iPad/Mac device availability or formally add and test those
   surfaces; rebuild.
2. Prevent auth request/response disk caching in both client and API, then prove
   the synthetic password sentinel is absent after login failure and process
   death.
3. Align OneSignal with production APNs and pass a real-device push matrix.
4. Add the Expo release channel, align build number 15, and remove/justify dev
   client/local-network residue.
5. Replace the Cielo OneLink/App Store target and verify share/unfurl on iPhone.
6. Reconcile PostHog behavior, privacy manifest, consent, legal copy, and App
   Store privacy labels.
7. Localize native permission strings and resolve the duplicate icon manifest.
8. Upload a new TestFlight build and repeat the anonymous computer proxy plus a
   real-iPhone critical path before any production promotion.
