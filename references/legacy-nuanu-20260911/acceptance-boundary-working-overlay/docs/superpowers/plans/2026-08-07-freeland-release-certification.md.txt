# Freeland Release Certification Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Produce reproducible, non-overlapping pre-deploy staging certification and post-deploy production-canary verdicts without treating individual ticket status as release approval.

**Architecture:** A pure release kernel consumes validated `QaRunEvidence`
pairs—one immutable `QaRunResult` plus its exact sanitized bundle and
registry-derived coverage projection—and exact
environment/candidate/catalog/policy/payment identities. It validates a
mandatory release registry and emits a signed-by-digest certification record.
Staging evidence can decide only the pre-deploy candidate verdict. A separately
attested production identity and production-only payment authorization create a
later canary record; failure creates an incident/rollback instruction but never
rewrites the staging decision. A parent-owned, authenticated Nuanu release-
control launcher keeps Nuanu credentials outside Freeland and exposes only
closed publish, pause, and incident operations over a fresh inherited FD `3`.
Only sanitized exact-version bundles cross into Nuanu Artifacts.

**Tech Stack:** Node.js 20.20.x, TypeScript 6, Node test runner, Ajv/JSON Schema, SHA-256 canonical JSON, existing FreelandQA contracts and coverage registry, Nuanu versioned Artifacts.

## Global Constraints

1. Implement product code only in `/Users/danilsolomin/projectsnew/NuanuFlowQA/.worktrees/freelandqa-personal-cdp-i1-local` from `codex/freeland-agent-first-cdp-i1-local@72378f3` or a reviewed descendant.
2. Read the runner and payment contracts from
   `packages/contracts/src/qa-run.ts` and
   `packages/contracts/src/payment-control.ts`; do not define substitute
   verdict or lifecycle types.
3. `Ready for prod` ticket count is never an input to candidate readiness.
4. Pre-deploy certification accepts staging evidence only. Post-deploy canary accepts production evidence only. Cross-environment evidence is a schema-valid blocked result, not a warning.
5. Candidate, full release SHA, catalog, integration, coverage, oracle, policy, environment, data, classifier, authorization, and payment-profile digests are exact-match invariants.
6. A zero-check, skipped, retried, expected-failure, stale, incomplete-evidence, unresolved-conflict, unknown-payment, failed-cleanup, or redaction-blocked mandatory leaf cannot yield ready/pass.
7. Publication may add Artifact references but cannot change a deterministic verdict.
8. Production failure opens a typed incident and pauses only the affected capability; it never edits historical staging certification.
9. Real production purchase is executed only through the separately completed payment plan and its production authorization. These tasks do not enter PAN/CVV or submit a charge directly.
10. All code tasks follow RED → minimal GREEN → focused regression → aggregate verification → exact-scope commit.
11. Production N3/N5 execution is one statically composed production runner:
    production-attributed Computer Use/CDP/Telegram/Playwright/API evidence
    first, the inert production payment factory last, and the common runner
    authority/evaluator/evidence publisher exactly once. It cannot import or
    invoke the N5 staging CLI or staging payment factory.
12. Nuanu credentials, endpoints, generic methods, executable paths, cwd,
    argv, descriptors, and environment keys remain parent-owned. Freeland
    release children receive only a fresh authenticated socket at FD `3`, exact
    non-secret deployment/handler pins, and the command-specific positive env
    allowlist.
13. The NuanuFlowQA and Freeland repositories own independent closed release-
    control types, JSON Schemas, and validators. Their pinned schema digests
    must match before launch; neither repository imports the other's source.
14. Every live release command is selected from the reviewed static handler
    manifest and spawned directly with pinned Node 20, `shell:false`,
    `detached:false`, fixed cwd/argv/stdio, and bounded I/O. Direct product CLI,
    npm, npx, shell, model, generic MCP, or caller-selected launch is not a live
    path.
