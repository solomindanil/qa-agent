# Freeland Deterministic Runner and Evidence Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Compose the existing Freeland coverage, Playwright, attestation, and evidence primitives into one closed-command deterministic N1 runner that emits schema-valid `QaRunResult` values and publishes only atomic sanitized evidence.

**Architecture:** Keep selection, execution-fact ingestion, evaluation, evidence construction, and artifact publication as separate deterministic modules behind one process-facing worker operation. The CLI accepts exactly one bounded `NuanuTaskEnvelope` whose `runnerCommandId` is `freeland-qa-run-v1`, then owns the complete plan → required lanes → freshness recheck → aggregate → sanitized publication sequence. Planning, lane execution, and aggregation are private functions, never ticket-selectable command IDs. A publisher port is the sole N1 boundary to Nuanu Artifact publication; Nuanu process state, task delivery, scheduling, retry, Decisions, and routing remain outside this repository layer.

**Tech Stack:** Node.js `>=20 <21`, TypeScript 6.0.3 in strict ESM mode, Playwright 1.61.1 JSON reporter, Node test runner through `tsx`, Ajv 8.20.0 plus `ajv-formats`, YAML 2.9.0, SHA-256, and POSIX atomic file publication.

`executeFreelandQaRun` is the only exported process-facing runner operation.
There is no public plan, lane, aggregate, scenario, project, or retry command.
The private functions `planQaRun`, `runPlaywrightLane`,
`ApiLaneExecutor.execute`, `evaluateQaRun`, and `publishQaRun` cannot be selected
or skipped by the envelope.

`prepareFreelandQaWorkerInput` is a trusted pre-dispatch materializer, not a
second runner command. It receives the already validated closed seed and the
trusted deployment's `identityPins`, which the static CLI constructed only
after authenticating the item/binding-selected mode, handler digest, and
deployment pin in the inherited control-session transcript. It loads and
validates the reviewed registry, plans the requirement closure, derives the
same full `QaRunIdentity` used by execution, and adds only the unbranded
lowercase 64-hex wire `qaRunKey`. It does not call `QaFreshnessAdapter` because
that exact port requires the already prepared `NuanuTaskEnvelope`; the first
freshness call occurs immediately after prepared-envelope validation and before
any lane. The seed and task JSON contain no execution mode; because the
authenticated pin mode is part of `QaRunIdentity`, the same seed under Manual,
Assist, and Auto derives three different keys. Preparation returns a frozen
`QaWorkerInputV1`; it cannot invoke a freshness read, lane, publisher, payment
adapter, or side effect.
`createFreelandRunnerPort.execute` calls only
`executeFreelandQaRun`, whose boundary validates the wire input into a branded
`NuanuTaskEnvelope`, independently reloads authority, and requires the prepared
key and authoritative execution mode to match before any lane. The Nuanu
remote-worker integration must
persist and replay the prepared envelope byte-for-byte; if that capability is
not proven, no live graph may activate.

`nuanu-worker-binding.ts` is the one static cross-repository composition root.
It imports `executeFreelandQaTask` and
`createDurablePreparedQaInvocationPort` only from the installed, vendored
`@nuanu/freeland-worker-adapter@1.0.0`, verifies the tarball and unpacked-entry
digests against `worker-adapter-lock.v1.json` before accepting a seed, creates
the local `FreelandRunnerPort`, validates the statically supplied repository
root and deployment pin, and internally derives/binds only the owned deployment-scoped
runtime directory
`<repositoryRoot>/.qa-runtime/prepared-invocations/<deploymentPinDigest>`.
The deployment pin is statically composed, lowercase SHA-256, and unique to
one execution mode/handler manifest; neither its value nor the root is task
input. A Manual→Assist→Auto transition creates a new immutable deployment pin,
authenticated session, and root before the next seed is accepted. An old root
is never consulted under a new pin, so an identical seed materializes once per
mode and cannot replay the prior mode's prepared key. The binding exposes no
module path, package path, command ID, invocation root, runner dependency, or
adapter override to task input. `.qa-runtime/` is ignored, owned `0700`, and
contains only the closed seed/key receipt bytes.

The vendored tarball is generated from a clean committed N0 checkout and is
installed with scripts disabled through the exact `file:vendor/...tgz`
dependency recorded in `package-lock.json`. The lock records the actual N0
source commit and SHA-256 values; the worker refuses an uncommitted source,
changed tarball, extra package entry, install hook, symlink, or lock mismatch.
No TypeScript source is imported from the sibling repository at runtime.
`tools/runner/run-nuanu-worker.ts` accepts no arguments, reads one bounded
`QaWorkerSeedV1` JSON value from stdin, invokes this binding, and writes only
the nine validated snake-case output fields plus one newline.

The three files `worker-handler.manual.v1.json`,
`worker-handler.assist.v1.json`, and `worker-handler.auto.v1.json` are the
official transport's sole executable handler manifests. Each contains an exact
literal `executionMode`; `nuanu-worker-handler.ts` validates its exact closed
keys and digest. `worker-adapter-lock.v1.json` records the closed three-entry
mode→handler-spec-digest map. For a claimed task, the official transport
resolves the selected Flow item's binding and authoritative process-control
mode, chooses exactly that map entry plus its separately immutable deployment
pin, and passes both as trusted composition inputs. The seed, task body, ticket,
graph, and environment may not select them. A transition between Manual,
Assist, and Auto requires a new deployment pin and exact control-plane
readback; a handler or deployment pin from another mode fails closed.
`selectFreelandNuanuWorkerHandler` rejects extra/missing map keys, requires all
three handler digests and all three deployment-pin digests to be pairwise
distinct lowercase SHA-256 values, and indexes the two maps only with the
authoritative mode. It verifies the selected manifest literal, lock digest,
deployment mode/digest, and handler digest before returning a spawn input.

The handler resolves `cwd` only to the already pinned product root and produces
one direct
`spawn` call with the exact Node/argv above, `shell:false`, `detached:false`,
seed on stdin, bounded result-only stdout, bounded coarse-code stderr, and the
transport-created authenticated control socket mapped to child FD `3`. The
transport never invokes npm, a package script, a shell, PATH lookup, or a model
prompt; therefore no npm banner can corrupt the one-JSON stdout protocol and
FD `3` reaches the final Node child directly. `qa:nuanu-worker` remains only a
local operator alias to the same argv. The selected lock entry and deployment
pin contain the same `handlerSpecDigest`; the manifest's literal mode, trusted
authoritative mode, deployment-pin mode, and child environment must also be
equal. A changed cwd, argv, env key, stdio mapping, limit, digest, mode, or
manifest byte keeps the handler inactive.

The manifest's required and optional environment-key tuples are the complete
positive allowlist shown in the interface. N1 activates no optional key; N3 may

copies values only after validating this exact tuple, authoritative mode,
selected handler digest, and deployment pin. It writes the already verified

`FREELAND_QA_HANDLER_SPEC_DIGEST`, and
`FREELAND_QA_DEPLOYMENT_PIN_DIGEST`; no parent or task value wins a conflict.

`nuanu-worker-ports.ts` is the only N1 consumer of the packaged inherited
control client. Its freshness adapter calls `captureFreshness` with the frozen

digest for the claimed `(task, qaRunKey, name)` fails closed.

The static CLI obtains `FREELAND_QA_DEPLOYMENT_PIN_DIGEST`,
`FREELAND_QA_HANDLER_SPEC_DIGEST`,
`FREELAND_QA_PROCESS_TEMPLATE_VERSION`, and one closed
`FREELAND_QA_EXECUTION_MODE=manual|assist|auto` value only from the official
handler's strict environment allowlist. Before reading stdin, it requires the
environment mode/digests to equal the selected manifest, adapter-lock entry,
and deployment pin. It then opens the authenticated inherited channel with
`createInheritedNuanuWorkerControlPort({ fd: 3, deploymentPinDigest,
handlerSpecDigest, executionMode })`. That authenticated session transcript is
the pre-preparation mode authority. Once preparation yields the exact envelope,
the first signed freshness response must contain the same mode before execution
authority or any lane is loaded, and the post-execution freshness read must
preserve it; any mismatch quarantines the prepared receipt, closes the channel,
and starts no lane or publication. It
calls the sole `createNuanuWorkerDependencies` static factory, which constructs
the trusted staging `RunnerDependencies` and replaces only the frozen-envelope

then creates the local runner port and packaged binding. The factory accepts no
extension-lane object, module path, callback, command, or task value. Its N1
implementation returns all four extension ports as null; N3 modifies this same
file to statically construct the reviewed CDP/Computer Use/Telegram executors,
and N5 modifies it again to add only the inert reviewed payment factory while
preserving those three ports. Every phase adds a packaged-worker integration
test; no later plan forks or replaces `run-nuanu-worker.ts`. The CLI
rejects any unexpected `NUANU_*` variable, task-provided override,
owner/migration/test/mutation variable, `NODE_OPTIONS`, `DYLD_*`, proxy,
loader/debug variable, or npm runtime-injection variable; it
never receives a Nuanu token or endpoint. The mode-specific deployment pin,
handler-spec digest, mode, and template version are identity pins selected by
item/binding authority, not task authority. Later N3/N5/N7 composition may
replace only the typed extension ports and reviewed environment profile behind
this same entrypoint; it cannot add another worker command or transport.

The N1 local factory sets `playwrightEnvironmentProfile: 'staging'` and all
four `extensionLanes` ports to `null`; N7 alone may construct a production
factory after its independent gate. This profile is trusted dependency state,
never an envelope field. The plan
and JSON schema already represent every later closed lane, but N1 selection
admits only current reviewed API/Playwright entries. N3 supplies the `cdp`,
`computerUse`, and `telegram` ports; N5 supplies an inert `payment` factory. A selected required
