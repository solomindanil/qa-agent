# Freeland Auto Routing and Continuous Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Promote only individually proven Freeland capabilities from Assist to safe automatic routing, with exact freshness guards and one-action rollback, then keep the complete requirement inventory current through scheduled drift analysis and controlled process experiments.

**Architecture:** FreelandQA deterministically derives capability eligibility and a content-addressed route intent from reviewed shadow evidence. A narrow Nuanu adapter applies that intent only when an atomic server-side revision/state/candidate guard succeeds and returns an exact transition receipt. A durable kill-switch state machine first disables new Ends, then reconciles in-flight journeys and touched items before leaving the capability in Assist. The same typed inventory feeds a scheduled Nuanu General Process for coverage drift; Nuanu Process Experiments compare orchestration variants while the deterministic oracle and frozen corpus remain unchanged.

**Tech Stack:** Node.js 20.20.x, TypeScript 6, Node test runner, JSON Schema/Ajv, SHA-256 canonical JSON, Nuanu Flow Column and General Processes, Nuanu Decisions/Artifacts/Process Experiments, existing FreelandQA coverage and release contracts.

## Global Constraints

1. Product code and product policy live in `/Users/danilsolomin/projectsnew/NuanuFlowQA/.worktrees/freelandqa-personal-cdp-i1-local` from `codex/freeland-agent-first-cdp-i1-local@72378f3` or its reviewed descendant.
2. Product-neutral Nuanu adapter/probe code lives in `/Users/danilsolomin/projectsnew/NuanuFlowQA/.worktrees/qa-auto-program` from `codex/qa-auto-program@affd6e1` or its reviewed descendant.
3. Never enable Auto project-wide. Every promotion names exact capability IDs and eligible verdict classes.
4. Minimum promotion evidence is 30 conclusive capability-specific shadow journeys over at least seven consecutive days, zero false green, zero false route, 100% reviewed precision for automatic `PRODUCT_FAIL`, zero duplicate/missing authoritative journeys, and no unresolved security finding.
5. Aggregate 98% Assist agreement cannot override a single capability-specific miss.
6. Ambiguous, stale, conflicting-lane, infrastructure, provider, flaky, incomplete-evidence, payment-unknown, and human-required results remain in Assist.
7. Payment execution authority and payment-related routing authority are separate promotions. Neither implies the other.
8. A local read-check-write is not a transition guard. Without a demonstrated atomic Nuanu revision/state/candidate guard, the adapter returns `ASSIST_REQUIRED` and performs no mutation.
9. Every mutation requires exact graph/policy/capability digests, precondition read, server receipt, read-back, audit record, idempotency key, and kill-switch generation.
10. Kill-switch activation precedes cancellation/takeover. Late completions from an older generation are rejected as stale.
11. `stop_flow_item_process` and `take_over_flow_item_process` execute only inside the declared rollback command and are recorded individually; they are not generic retry behavior.
12. Nuanu owns journeys, task leases, Decisions, states, and Process Experiments. Do not build a second scheduler, queue, journey engine, or experiment platform.
13. An inventory exception is typed, owned, expiring, and evidenced. `MISSING` can never silently count as covered.
14. PostgreSQL stores only capability mode/generation and append-only safety
    receipts; it is not a task queue, journey store, scheduler, or replacement
    for Nuanu.
15. Every code task follows RED → minimal GREEN → focused regression → aggregate verification → exact-scope commit.
