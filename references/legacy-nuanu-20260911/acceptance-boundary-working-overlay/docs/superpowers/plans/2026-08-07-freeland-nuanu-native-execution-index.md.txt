# Freeland Nuanu-Native QA Program Execution Index

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver the approved Freeland autonomous QA product without rebuilding Nuanu Flow's orchestration layer, while preserving deterministic browser, evidence, payment, and routing safety.

**Architecture:** Nuanu Flow owns Column and General Processes, BPMN journeys, remote-agent task delivery, Decisions, transition receipts, sanitized Artifacts, and Process Experiments. `NuanuFlowQA` owns reusable process contracts; the private `FreelandQA-I1` repository owns Freeland coverage, the deterministic runner, CDP/Computer Use, personas, payment safety, and release verdicts. This index coordinates six independently reviewable implementation plans whose outputs form one end-to-end path.

**Tech Stack:** Node.js 20.20.x, TypeScript 6, Playwright 1.61.1, Nuanu Flow structured process graphs and remote Codex workers, PostgreSQL 16 for payment-domain atomicity, macOS Chrome/Computer Use, Telegram Web, JSON Schema/Ajv, versioned Nuanu Artifacts.

## Global Constraints

1. The approved design is `docs/superpowers/specs/2026-08-07-freeland-nuanu-native-qa-control-plane-design.md` at commit `affd6e1`.
2. Do not build a second workflow engine, generic task queue, generic worker lease system, agent registry, Decision inbox, or sanitized Artifact registry.
3. Nuanu process graphs are structured nodes and edges, never raw BPMN XML.
4. Every Column Process preserves the server-generated `project_process_start` byte-for-byte and uses explicit `project_status.target_state_id`; `null` is the QA-hold End.
5. The first live graph is Manual, then Assist. Auto is capability-scoped and remains disabled until the exact race, shadow, receipt, and kill-switch gates pass.
6. The deterministic FreelandQA evaluator owns `issueVerdict` and `candidateVerdict`; agent prose cannot modify either result.
7. Computer Use is the primary black-box lane for user-visible Freeland flows. Playwright/API is the faster deterministic secondary lane and cannot replace a required Computer Use or real Telegram observation.
8. Real staging and production canaries are owner-authorized without per-purchase confirmation, but every submit requires the durable authorization, budget, canonical-intent, mutex, fencing, scrub, and reconciliation gates.
9. A Nuanu task retry may repeat observation or reconciliation and must never repeat payment submission.
10. Full PAN, CVV, cookies, storage state, tokens, signed URLs, personal data, and raw provider payloads never enter Git, Nuanu, ordinary logs, Playwright reports, or agent prompts.
11. Nuanu Artifacts contain only sanitized exact-version derivatives. Restricted raw evidence remains outside Nuanu and follows its own scrub, TTL, deletion-receipt, and tombstone policy.
12. `Ready for prod` on one ticket never implies `CANDIDATE_RELEASE_READY`; pre-deploy staging certification and post-deploy production canary are separate verdicts.
13. A false green, stale End transition, duplicate submit, unknown payment outcome, wrong origin, or failed scrub pauses the affected lane and prevents routing.
14. Use Node `20.20.x` for authoritative FreelandQA commands. Do not accept an ambient Node 22 run as completion evidence.
15. Preserve the user's dirty root worktree. All documentation changes in this program branch and all product implementation changes in a dedicated clean FreelandQA worktree.
16. Every code task follows strict RED → minimal GREEN → focused regression → aggregate verification → exact-scope commit.

`QaRunResult`, `PaymentLifecycle`, and their JSON Schemas are introduced by the
deterministic-runner plan. Every later plan imports them from
`packages/contracts/src/qa-run.ts`; no subsystem creates a similar local type.
The same N1 contract predeclares closed `QaPlannedLane` variants for API,
Playwright, CDP, Computer Use, Telegram, and payment plus nullable
`RunnerDependencies.extensionLanes` ports. N1 leaves later ports null, N3 fills
CDP/Computer Use/Telegram, and N5 fills payment; all still terminate in the one
`executeFreelandQaRun` aggregate and `QaRunResult`.

Nuanu supplies a closed `QaWorkerSeedV1` without `qaRunKey`. The trusted N1
preparation port plans against private reviewed authority, derives the complete
identity, and returns one frozen wire `QaWorkerInputV1`. The Nuanu worker binding
must implement N0's `PreparedQaInvocationPort.materializeOnce`, durably commit
and replay those exact prepared bytes before the sole command dispatches, and
never call preparation again for the same seed digest. The N1 execution boundary validates and brands that
wire value as `NuanuTaskEnvelope`; the independent Nuanu adapter validates the complete
`QaRunResult` schema, requires exactly one artifact reference, and maps only the
nine exact snake-case graph outputs. Failure to prove prepared-input replay
keeps the live graph inactive.

The two repositories are composed by one reviewed package boundary, not a
sibling-source import. N0 builds `@nuanu/freeland-worker-adapter@1.0.0`; N1
vendors the compiled tarball and pins its N0 source commit, tarball SHA-256, and
entry digest. N1's `qa:nuanu-worker` static binding verifies that lock, creates
the N1 `FreelandRunnerPort` plus N0 durable `PreparedQaInvocationPort`, and is
the only handler mapped by the official remote-worker transport for
`freeland-qa-run-v1`. The official handler passes an authenticated task-scoped
control socket only as inherited file descriptor `3`; the static binding adapts
its two closed operations to authoritative freshness and one sanitized Artifact
publication, while the child receives no Nuanu token, endpoint, generic method,
or task-controlled environment value. Its end-to-end test and N0 Manual probe cover seed,
materialization, prepare-once, execute, nine-field projection, and restart/
reclaim replay. A source, package, handler-map, or durable-root mismatch keeps
the Column binding inactive.

N1 also publishes a sanitized `QaCoverageProjection` inside every
`QaArtifactBundle`, binding Flow item, requirements, checks, capabilities, and
lanes to the same key. N6 certification and N8 routing consume validated
`QaRunEvidence` pairs (result plus exact bundle/projection), never result counts
or lane digests alone.

## Program Acceptance Sequence

- [ ] **Gate A — static contracts:** both repositories typecheck; graph, result,
  and evidence fixtures validate; FreelandQA selects at least one executable
  check for every accepted fixture.
- [ ] **Gate B — local deterministic slice:** known-good, known-bad, stale,
  infra-failure, incomplete-evidence, retry-only, and empty-selection fixtures
  receive their exact non-overlapping verdicts.
- [ ] **Gate C — Manual Nuanu slice:** one synthetic/non-critical item reaches
  approve, deny, refine, QA-hold, and restart paths without changing status.
- [ ] **Gate D — real black-box lanes:** public web Computer Use and real
  Telegram Web observations bind to exact candidate/session identities and
  agree with required Playwright/API lanes.
- [ ] **Gate E — Assist calibration:** 30–50 blinded cases, at least 98%
  reviewed agreement, zero critical false green, zero wrong issue/candidate,
  zero missing authoritative journeys.
- [ ] **Gate F — staging payment:** normal paid, declined/cancelled, and forced
  unknown paths prove one-checkout/one-submit, budget hold, fence, watchdog,
  scrub, and external reconciliation; the payment lane is aggregated by the
  same `executeFreelandQaRun` path and returned in its single `QaRunResult`.
- [ ] **Gate G — release split:** pre-deploy staging candidate verdict contains
  only staging evidence; post-deploy production canary uses a separate
  authorization/account/catalog/evidence identity.
- [ ] **Gate H — Limited Auto:** each capability has at least 30 conclusive
  shadow journeys over seven consecutive days, zero false green/route, 100%
  reviewed PRODUCT_FAIL precision, exact receipts, and a successful in-flight
  kill-switch rollback drill.
- [ ] **Gate I — continuous inventory:** every active requirement is automated,
  explicitly blocked, or inapplicable with reviewed current evidence; drift
  creates a typed gap instead of a silent coverage reduction.

## Overall Definition of Done

The program is complete only when all six implementation plans are complete,
all Gates A–I have immutable evidence, the exact active Nuanu graph version has
been read back, sanitized Artifacts are linked to the corresponding work item
and process run, payment data has no out-of-boundary copy, and every enabled
Auto capability has a tested one-action rollback to Assist. Completion of a
Nuanu feature, a plan file, or the CDP library alone does not satisfy this
definition.

reviews. After both pass, execute Plans 3–6 in dependency order. The controller
must update a single progress ledger with commit OIDs, RED/GREEN commands,
