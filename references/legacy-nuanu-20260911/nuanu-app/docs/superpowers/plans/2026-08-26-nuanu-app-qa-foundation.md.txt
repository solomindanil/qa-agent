# Nuanu App QA Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the standalone Nuanu App Playwright entry, fail-safe browser
instrumentation, deterministic product graph, source/runtime identity model,
impact planner, and dry-run CLI.

**Architecture:** Nuanu App gets product-local tests and graph tooling. Source
identity and observed runtime identity remain separate inputs; the graph joins
them only through reviewed mappings and provenance. The foundation can list and
plan tests without credentials, remote writes, or another product graph.

**Tech Stack:** TypeScript 6, Playwright 1.61, Node.js ESM, node:test, Git,
JSON artifacts.

**Spec:** `docs/superpowers/specs/2026-08-26-nuanu-app-qa-project-design.md`

## Global Constraints

- V1 tests only `https://app.nuanu.com/` as web/PWA. Native builds are out of
  scope.
- The upstream `nuanu-ai/nuanu-web` repository is read-only: no push, PR,
  issue, commit, or source modification.
- Do not import, read, write, refactor, or depend on any other product graph,
  mapping, test tree, generated state, or CLI.
- Product-local paths use `nuanu-app`; stable graph IDs start with
  `nuanu-app:`.
- The only shared-file edits allowed are narrow Nuanu App additions to
  `playwright.config.ts`, `.env.example`, and `package.json`.
- Preserve all existing dirty work. Before each shared-file edit, inspect the
  current diff; stage only exact owned paths.
- Browser activity is read-only by default. Non-GET/HEAD/OPTIONS requests are
  blocked in public interaction tests and recorded without query strings or
  bodies.
- Missing credentials, mappings, baselines, or devices produce explicit
  BLOCKED, UNVERIFIED, MANUAL, or INCONCLUSIVE status; never PASS.
- Every task follows red-green-refactor and ends with focused verification plus
  an exact-path commit.
- Run superpowers:verification-before-completion before any completion claim.

`buildTestPlan` returns these exact disposition buckets in deterministic ID
order:

~~~js
{
  selectedAutomated: [],
  manual: [],
  blocked: [],
  notDeployed: [],
  unverified: [],
  fallbackApplied: false,
  telemetrySignals: [], // present only when the optional input is non-empty
}
~~~

Source-only cases with `coverageDisposition: "UNVERIFIED"` are emitted only in
`unverified`; they are never placed in `blocked` and never selected as live
tests. `blocked` remains reserved for a real unavailable prerequisite.
`telemetrySignals` retains its own `select`, `observe_only`, `suppressed`, or
`blocked` disposition and is not folded into any case-status bucket.

`buildTestPlan` also accepts the explicit runtime-only impact shape emitted by
Task 7:

~~~js
{
  mode: "runtime_only",
  changedFiles: [],
  affectedNodeIds: [],
  unmappedFiles: [],
  paths: [],
  sourceImpact: "UNVERIFIED",
}
~~~

It must be a plain JSON object with exactly those fields. Missing/extra fields,
custom prototypes, source proof, or non-empty arrays fail before selection.
That mode applies the existing safe full fallback: all discovered runnable
read-only tests whose live target can be verified, plus the eligible mobile
safety tier. It does not collapse `unverified`, `blocked`, `manual`, or
`notDeployed` into selected coverage. Source-impact planning keeps accepting
the legacy shape without `mode`; explicit `mode: "source_diff"` is equivalent
for compatibility. Every other explicit `mode` value is rejected before
selection.

All validation functions return:

~~~js
{ ok: boolean, errors: Array<{ code: string, message: string, path?: string }> }
~~~

Task 6 uses the following exact optional telemetry selector schema. Every field
is required and unknown fields are rejected:

~~~js
{
  id: "napp-telemetry-v1-" + lowercaseSha256,
  productId: "nuanu-app",
  catalogDigest: lowercaseSha256,
  mappingId: "napp-telemetry-map-v1:route-health" | null,
  metricId: "route-health",
  disposition: "select" | "observe_only" | "suppressed" | "blocked",
  kind: "observed" | "regression",
  priority: "informational" | "elevated",
  targetNodeIds: ["nuanu-app:route:root"],
}
~~~

`mappingId` is explicitly a namespaced string or JSON `null`; omission and
`undefined` are invalid. Mapped targets are sorted, unique, existing Nuanu App
non-source nodes. An unmapped selector has `mappingId: null` and an empty
`targetNodeIds`; only an elevated regression with `disposition: "select"` may
expand the existing full safe fallback. Other unmapped selectors retain
`sourceImpact: "UNVERIFIED"` in the returned `telemetrySignals` summary.

Telemetry selections preserve the legacy top-level selection reason and add a
typed `reasons[]` detail:

~~~js
{
  id: "nuanu-app:auto:tests/nuanu-app/public/smoke.spec.ts#NAPP-PUB-001 ...",
  reason: "telemetry_signal",
  reasons: [{
    code: "telemetry_signal",
    signalId: "napp-telemetry-v1-" + lowercaseSha256,
    mappingId: "napp-telemetry-map-v1:route-health",
    catalogDigest: lowercaseSha256,
    graphPath: [
      "nuanu-app:auto:tests/nuanu-app/public/smoke.spec.ts#NAPP-PUB-001 ...",
      "nuanu-app:route:root",
    ],
  }],
}
~~~

When deterministic impact or policy already selected the test, its top-level
`reason`, `path`, or `policy` stays intact and `reasons[]` contains both the
deterministic reason and the telemetry reason. An elevated unmapped regression
uses top-level `reason: "full_fallback"` and a `reasons[]` entry containing
`code`, `signalId`, and `catalogDigest`. Telemetry is add-only: it never removes
a test, creates a verdict, proves deployment identity, promotes
BLOCKED/MANUAL/NOT_DEPLOYED work, or creates a Flow item.

- [ ] **Step 3: Implement the exact safety contract**

~~~ts
import type { Page } from '@playwright/test';

export type BlockedMutation = Readonly<{ method: string; url: string }>;
const SAFE_METHODS = new Set(['GET', 'HEAD', 'OPTIONS']);

export function sanitizeUrl(raw: string): string {
  const url = new URL(raw);
  return url.origin + url.pathname;
}

export async function blockUnsafeRequests(
  page: Page,
  blocked: BlockedMutation[],
): Promise<void> {
  await page.route('**/*', async (route) => {
    const request = route.request();
    const method = request.method().toUpperCase();
    if (SAFE_METHODS.has(method)) {
      await route.continue();
      return;
    }
    blocked.push({ method, url: sanitizeUrl(request.url()) });
    await route.abort('blockedbyclient');
  });
}
~~~

No request body, query, header, cookie, or storage value is collected.

import { createHash } from "node:crypto";

export const PRODUCT_ID = "nuanu-app";
export const GRAPH_SCHEMA_VERSION = "1.0.0";

export function canonicalize(value) {
  if (Array.isArray(value)) return value.map(canonicalize);
  if (value && typeof value === "object") {
    return Object.fromEntries(
      Object.keys(value).sort().map((key) => [key, canonicalize(value[key])]),
    );
  }
  return value;
}

export function digestJson(value) {
  return createHash("sha256")
    .update(JSON.stringify(canonicalize(value)))
    .digest("hex");
}
~~~

- [ ] **Step 4: Implement CLI commands**

Required usage:

~~~text
node tools/nuanu-app-graph/cli.mjs init
node tools/nuanu-app-graph/cli.mjs source-lock --repo "$NUANU_APP_SOURCE_REPO"
node tools/nuanu-app-graph/cli.mjs runtime --url https://app.nuanu.com
node tools/nuanu-app-graph/cli.mjs validate
node tools/nuanu-app-graph/cli.mjs validate --refresh
node tools/nuanu-app-graph/cli.mjs plan --runtime-only --dry-run
node tools/nuanu-app-graph/cli.mjs plan --repo "$NUANU_APP_SOURCE_REPO" --from "$BASELINE_SHA" --to "$CANDIDATE_SHA" --dry-run
~~~

Plain `validate` creates the initial graph or attests that an existing graph
still matches the current normalized runtime, reviewed mappings, source lock,
and Playwright `--list` catalog. It returns `STALE_GRAPH` without writing when
a structurally valid stored graph has different current input digests.
`validate --refresh` is the only explicit mode-switch path: it requires an
existing structurally valid, product-correct, self-attested graph, validates
all current inputs normally, and may then atomically replace a semantically
stale graph without relaxing stored-graph integrity checks. Its compact
success summary includes `refreshed:true`. Unknown, duplicate, equals-form,
positional, and all other `validate` options are usage errors.

`plan --runtime-only` emits the locked empty-array `mode: "runtime_only"`
impact and delegates to the safe full fallback. It cannot be combined with
source-diff arguments. Any unknown planning mode fails before an impact or test
plan is written.

`NUANU_APP_SOURCE_REPO` must be a user-supplied absolute read-only checkout;
the CLI rejects empty, relative, dirty, wrong-remote, and symlink-escaping
paths. `BASELINE_SHA` and `CANDIDATE_SHA` must be full 40-character commits
present in that checkout. The recon SHA
`2fdbcf8267c57e336c73454e0888d5eaa2a95d7b` is recorded only as historical
reference and is never an execution prerequisite. No command executes
Playwright tests, changes Flow, or writes upstream source.

The foundation is complete only when:

- all standalone graph unit tests pass;
- graph validation and dry-run planning work from private Nuanu paths;
- source-only and runtime-only provenance cannot create false live coverage;
- source-only UNVERIFIED cases are reported distinctly from BLOCKED cases;
- optional aggregate telemetry is add-only, privacy-shaped, and cannot create
  a verdict or block deterministic coverage when absent;

- all manual/auth/native/visual/performance gaps remain explicit.
