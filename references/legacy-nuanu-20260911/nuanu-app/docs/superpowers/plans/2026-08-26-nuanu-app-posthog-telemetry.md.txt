# Nuanu App PostHog Aggregate Telemetry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an optional privacy-normalized PostHog evidence lane that reads
only reviewed aggregate metrics, produces add-only graph-planner signals, and
records a non-gating first baseline for `app.nuanu.com`.

**Architecture:** Pure normalization rejects raw or identifying analytics data
before persistence. Code-owned immutable builders generate only recursively
allowlisted PostHog structured queries, inject the mandatory
`app.nuanu.com` equality scope, validate the complete query, and hash it before
an exact-host/project/path transport can run. Each p75 query is an immutable
pair with an independently aggregated total-count companion for privacy-floor
sample size. Reviewed telemetry mappings may add safe tests to the deterministic
plan, but telemetry never supplies PASS/FAIL, source/runtime/deployment proof,
release approval, or automatic defect creation.

**Tech Stack:** Node.js ESM, node:test, canonical JSON digests, code-owned
PostHog structured-query builders, injected host secret provider, exact-scope
POST transport, existing Nuanu App graph planner, private JSON artifacts.

**Spec:** `docs/superpowers/specs/2026-08-26-nuanu-app-qa-project-design.md`

## Global Constraints

- V1 is standalone and covers only `https://app.nuanu.com/` web/PWA. Do not
  import from or write to another product graph or analytics project.
- Complete Tasks 1–3 with synthetic fixtures only. Do not open an invitation,
  use a live account, or execute a live analytics query before Task 4.
- PostHog is optional aggregate evidence. Its only planner authority is to add
  discovered read-only automated tests or, for a separately reviewed elevated
  unmapped regression, expand the existing full safe fallback and mobile
  manual safety tier.
- Telemetry never removes a test, changes a result status, proves source,
  runtime, release, or deployment identity, gates a release, or automatically
  creates a Nuanu Flow Bugs item.
- Source-only UNVERIFIED cases remain in the planner's distinct sorted
  `unverified` bucket. Telemetry cannot promote or reclassify them and its own
  dispositions remain separate from case-status buckets.
- Missing access blocks only telemetry as `BLOCKED`. Missing event/property
  schema is `NOT_INSTRUMENTED`. A complete supported primary whose exact
  companion/result cannot be used is `UNAVAILABLE`. A cohort below 20 is
  `SUPPRESSED`. The deterministic web/PWA
  campaign continues in every case.
- Do not read, retain, attach, or export raw events, persons, session replays,
  exact URLs or query values, person/session/device identifiers, IP addresses,
  precise GPS, email or phone data, search text, exception messages, stacks or
  code variables, request headers, or request/response bodies.
- After the 20-observation floor, persist only explicitly allowlisted public
  browser/OS/device/PWA/release categorical values. A present dimension
  allowlist requires an exact match; mismatch rejects and never silently
  randomizes. An omitted dimension uses one catalog-wide ephemeral random-ID
  memo with no persisted reverse map. Unkeyed hashes are never described or
  used as a privacy boundary.
- JavaScript exception evidence stores only total count/rate unless the
  official schema proves a provider fingerprint is already opaque and its
  dedicated mutually exclusive auxiliary query/hash is approved; even then,
  retain it only for a group with at least 20 observations. Otherwise use
  `FIELD_NOT_PROVEN` and retain aggregate exceptions only.
- Durable numeric evidence is limited to sample size and aggregate count,
  rate, or p75 value; freshness may retain a completed aggregate bucket
  timestamp.
- Every adapter receives one explicit immutable canonical UTC-midnight 24-hour
  UTC window. No component derives it from the current clock; it is included
  in every query and approved hash.
- Non-p75 sample size comes only from the code-owned sole total, ordered rate
  denominator, or funnel first-step population, never a result/row/bucket/
  array length.
- A p75 `sampleSize` comes only from an independent `total` companion query
  over the identical event population, UTC window, app-host predicate,
  filters, and breakdown. Pair by immutable metric ID, completed bucket, and
  ordered dimensions—not response order, array length, quantile payload, or
  result metadata. Missing, mismatched, duplicate, ambiguous, or unsupported
  count evidence makes that p75 UNAVAILABLE.
- Only the percentile-primary and sample-count envelopes inside one validated
  `postStructuredP75Pair` call may remain structurally valid with duplicate
  full coordinates. That is semantic pair ambiguity and yields UNAVAILABLE with
  `P75_COUNT_PAIR_AMBIGUOUS`, not `HTTP_PROVIDER_BLOCKED`; the latter is
  reserved for envelope shape/type/bounds/required-uniqueness, redirect, or
  status failure.
- Every non-p75 primary and exception-fingerprint auxiliary envelope requires
  structurally unique full coordinates. A duplicate maps to
  `HTTP_PROVIDER_BLOCKED` with zero candidate emission; it never reaches metric
  normalization or p75 ambiguity classification.
- Suppress every overall or breakdown cohort whose sample size is below 20.
  Do not persist its value, provider fingerprint, or random ID; retain only an
  incremented `suppressedCohortCount`.
- A credential is never an argument, environment example, log, artifact,
  command-line value, or chat value. Query authentication remains inside the
  host secret provider or approved connector; the browser session cannot be
  substituted.
- Bind live reads to one exact host, target project resource, and query
  endpoint path. The private manifest may bind strictly validated identifiers
  to a code-owned builder ID but cannot supply any query body.
- Reject `HogQLQuery`, SQL/HogQL text, raw-table/column nodes, person/replay/raw
  event queries, joins, and unknown structured-query fields before the injected
  client is called. Future HogQL stays BLOCKED pending a separately reviewed
  AST allowlist.
- Recursively validate the complete generated structured query, inject one
  exact-equality predicate for a freshly inspected host/environment property
  equal to `app.nuanu.com` into every query, then hash it. If that mapping is
  missing or unreliable, telemetry is BLOCKED or NOT_INSTRUMENTED and selects
  no tests.
- Validate one closed schema observation with one preflight identity/digest,
  all nine metric statuses, all five breakdown statuses, exact project/
  capability evidence, and age no greater than 30 minutes. Builders prove only
  structural binding/query/window shape; the Task 2 read layer proves
  freshness and same-preflight manifest/access-lock binding.
- For every p75 builder, recursively validate and allowlist both the percentile
  query and its independent total-count companion plus their pair digest before
  either transport call. A companion count below 20 suppresses both the p75
  value and cohort identity.
- Task 2 alone sees and joins provider aggregate responses. Task 1 accepts only
  its exact candidate, validates structural attestations/tagged unions, applies
  privacy, and makes no raw-origin or schema-freshness claim.
- The exact PostHog host is control-plane scope metadata and the sole allowed
  exact URL. No product/event URL or query value is collected or persisted.
- Do not infer effective permissions from a role name or one `readOnly` flag.
  Inspect and read back the full capability matrix defined below.
- The invitation web session is only for invite, schema, and capability
  read-back. It is not API authentication. Automated reads require a separately
  scoped `query:read` credential from macOS Keychain/CI secret storage or an
  approved connector; without one telemetry remains BLOCKED.
- Do not change PostHog project settings, instrumentation, feature flags,
  cohorts, dashboards, retention, annotations, users, roles, or product data.
  Accepting one exact invitation after action-time confirmation is the only
  authorized PostHog mutation in this plan.
- Normalize responses in memory and discard them. HTTP 401, 403, 429, and 5xx
  are telemetry BLOCKED; never persist their response data. Accept only the
  bounded closed status/redirect/payload/coordinate envelope. Malformed 200,
  redirect, unexpected status, or shape/size mismatch uses
  `HTTP_PROVIDER_BLOCKED`. Production compatibility remains UNVERIFIED until
  Task 4 reads back the live schema and connector contract.
- Persist only the exact six-field telemetry catalog wrapper. Its canonical
  digest excludes only itself and includes `capturedAt`.
- The first baseline has no approved thresholds. PostHog real-user metrics do
  not replace the five-run named lab performance baseline and do not gate a
  release.
- Preserve existing dirty work. Commit only the exact tracked files named by
  each task; private live artifacts under `docs/local` remain untracked.
- Run `superpowers:verification-before-completion` before any completion claim.

`window` is a required immutable adapter argument, never an implicit clock
calculation. V1 accepts exactly a plain object
`{ startAt, endAt, interval: "day" }`: both timestamps use canonical
`YYYY-MM-DDT00:00:00.000Z`, `endAt` is exactly 24 hours after `startAt`, and
the logical interval is `[startAt, endAt)`. `validateAndFreezePostHogWindow`
rejects extra keys, offsets, fractional/unaligned times, invalid calendar
values, a different or non-positive duration, and mutation-prone nested input;
it returns a defensive deeply frozen copy. Every generated query contains
these exact bounds, so every approved query hash is window-dependent. Neither
the adapter, builder, transport, nor a retry may derive a boundary from
`Date.now()` or injected `now`; `now` is used only for schema freshness and the
single catalog `capturedAt`.

`POSTHOG_QUERY_BUILDERS` is this complete immutable V1 map. Array position is
the provider-series position and is part of validation; there is no generic
fallback builder.

| query ID | builder ID / node | exact ordered code-owned roles and aggregation | durable value and `sampleSize` origin |
| --- | --- | --- | --- |
| `telemetry-freshness` | `trends-total-v1` / `TrendsQuery` | `[population_event: total]` | `count = population_event`; `sampleSize = population_event` count; freshness age is `capturedAt - bucketEndedAt` only |
| `route-health` | `trends-route-health-rate-v1` / `TrendsQuery` | `[route_attempt_population: unique_session, route_success_population: unique_session]` | `rate = success / attempt`; `sampleSize = attempt` denominator |
| `funnel-discovery` | `funnels-discovery-v1` / `FunnelsQuery` | `[discovery_surface_view, place_detail_view_from_discovery]`, each `total` | `rate = last / first`; `sampleSize = first-step` population |
| `funnel-search` | `funnels-search-v1` / `FunnelsQuery` | `[search_submit, search_results_view, place_detail_view_from_search]`, each `total` | `rate = last / first`; `sampleSize = first-step` population |
| `funnel-place-detail` | `funnels-place-detail-v1` / `FunnelsQuery` | `[place_detail_view, place_detail_primary_action]`, each `total` | `rate = last / first`; `sampleSize = first-step` population |
| `js-exception-rate` | `trends-exception-session-rate-v1` / `TrendsQuery` | `[eligible_session_population: unique_session, exception_session_population: unique_session]` | `rate = exception sessions / eligible sessions`; `sampleSize = eligible-session` denominator |
| each of `web-vitals-lcp-p75`, `web-vitals-cls-p75`, `web-vitals-inp-p75` | `trends-p75-v1` / `TrendsQuery` | primary `[vital_measurement: p75]`; companion `[vital_measurement: total]` | `p75` from primary; `sampleSize` only from independently returned companion count |

The only auxiliary map entry is
`js-exception-rate:fingerprint -> trends-exception-fingerprint-breakdown-v1`
with exactly one `exception_session_population: unique_session` series and the proven
fingerprint breakdown. No other logical or auxiliary query ID is accepted.

The two rate builders reject a zero/missing denominator and numerator greater
than denominator. Funnel builders use the exact adapter date range plus
`funnelWindowInterval: 24`, `funnelWindowIntervalUnit: "hour"`; they reject a
missing first step, later-step population greater than the first step, or a
provider response with a different order/arity. `route-health` means only the
instrumented share of schema-proven route attempts that reached the
schema-proven route-success event during this window. It is not HTTP uptime,
deployment health, source/runtime proof, or a release gate. If those semantic
roles are not proven by the fresh schema observation, the metric is
`NOT_INSTRUMENTED`; a similarly named event is never substituted.

No metric obtains `sampleSize` from response-array length, number of returned
rows/buckets, quantile metadata, or a result-object count. A code-owned
companion series/query is mandatory whenever the primary response does not
itself contain the exact reviewed population named in the table. Unsupported
exact population evidence makes only that metric `UNAVAILABLE` after a primary
hash exists, or `NOT_INSTRUMENTED` when the required event/value binding does
not exist.

The code-owned builders emit only these recursively validated structures:


`FunnelsQuery` permits exactly `kind`, `series`, `dateRange`, `properties`, and
`funnelsFilter`; every series entry is an `EventsNode` with a schema-bound event
and fixed `math: "total"`, and every V1 funnel binding requires
`breakdown: null`. `funnelsFilter` permits only `layout: "vertical"`,
`funnelVizType: "steps"`, `funnelWindowInterval: 24`, and
`funnelWindowIntervalUnit: "hour"`. No other root or
nested field is accepted. A structured p75 query is emitted only when the
binding structurally contains the exact p75 value-property slot; the Task 2
read layer, not the builder, proves that slot against fresh schema facts before
transport. A missing bound event/value property is NOT_INSTRUMENTED instead.
The builders never fall back to text query or `math: "hogql"`.

There is exactly one p75-pair digest input and algorithm in V1. The shared
`createP75PairDigestInput` returns this exact plain object with no extra keys:

~~~js
{
  metricId: "web-vitals-lcp-p75",
  dimensions: ["browser"],
  percentile: {
    role: "p75_value",
    queryHash: lowercaseSha256,
  },
  sampleCount: {
    role: "sample_count",
    queryHash: differentLowercaseSha256,
  },
}
~~~

`dimensions` is a sorted unique array of reviewed dimension IDs; `[]` means
the overall metric. `digestP75Pair` rejects missing/extra keys, unknown metric
or dimension IDs, unsorted/duplicate dimensions, wrong roles, malformed
hashes, and equal role hashes. It returns `digestJson(p75PairDigestInput)` from
`model.mjs`: UTF-8 JSON of recursively key-sorted objects while preserving
array order, SHA-256 encoded as lowercase hex. Nothing else enters the digest.
Both `telemetry.mjs` and the Task 2 query/transport modules import this shared
helper; no second pair-digest implementation is permitted.

`buildP75PostHogQueryPair` emits this immutable in-memory bundle for each Web
Vital metric:

~~~js
{
  p75PairDigestInput: exactObjectAbove,
  pairDigest: lowercaseSha256,
  percentileQuery: structuredTrendsQueryWithExactlyOneP75Series,
  sampleCountQuery: structuredTrendsQueryWithExactlyOneTotalSeries,
}
~~~

Its return is this strict builder-result union:

~~~js
{
  status: "READY",
  queryHash: p75PairDigestInput.percentile.queryHash,
  pairBundle: immutableBundleAbove,
  limitation: null,
} | {
  status: "UNAVAILABLE",
  queryHash: completedPrimaryPercentileQueryHash,
  pairBundle: null,
  limitation: "P75_COUNT_COMPANION_UNAVAILABLE",
}
~~~

The second branch is valid only when the primary percentile query was built
and hashed but an exact companion cannot be expressed/proven; it authorizes no
transport. Failure to build a complete primary structured query is pre-query
BLOCKED with `queryHash: null`, not an UNAVAILABLE builder result.

Both queries use the same schema-bound event, UTC date range, interval, exact
`app.nuanu.com` predicate, other root/series filters, and breakdown definition.
The percentile series alone carries the schema-bound value property and p75
math; the count series uses `math: "total"` and no value aggregation. Schema
facts must prove that this total series counts exactly the percentile-eligible
event population. If identical population semantics cannot be expressed with
the allowed structured fields, the p75 metric is UNAVAILABLE.

Pair validation hashes each complete query, requires those hashes to equal the
two role hashes in `p75PairDigestInput`, recomputes `pairDigest` only through
the shared helper, and checks every field above. Missing, duplicate, or extra
pair fields, reversed roles, or any window/event/host/filter/breakdown mismatch
reject the pair before transport. Neither individual query hash can authorize
a p75 read without the approved `pairDigest`.

The recursive validator rejects before transport: `HogQLQuery`; any SQL/HogQL
string field; raw `EventsQuery`; persons, session-recording, replay,
data-warehouse, or raw-table nodes; `source`, `table`, `columns`, `select`, or
join fields; raw URL/person/session properties; unknown fields; aggregation or
operator values outside the constants above; and any query lacking exactly one
host predicate equal to `app.nuanu.com` for the property identifier supplied
by the exact binding. This builder validation is deliberately structural and
non-circular: it accepts only `{query, binding, window}` (or
`{pair, binding, window}`), never `accessLock`, `schemaFacts`, a manifest, or
`now`. `posthog-read.mjs` separately proves that the binding belongs to a fresh
schema observation, then compares its rebuilt hash with the final access lock.

`schema-facts.v1.json` is the only status authority for instrumentation. It has
this exact closed shape:

~~~js
{
  version: 1,
  provider: "posthog",
  productId: "nuanu-app",
  targetHost: "app.nuanu.com",
  observation: {
    preflightId: "napp-posthog-preflight-" + randomUuid,
    observedAt: "canonical ISO UTC timestamp",
    targetProjectResourceId: exactPrivateTargetProjectResource,
    capabilityEvidenceDigest: lowercaseSha256,
    evidenceDigest: lowercaseSha256,
  },
  hostScope: {
    status: "AVAILABLE" | "NOT_INSTRUMENTED",
    kind: "event_property",
    propertyIdentifier: schemaBoundHostPropertyOrNull,
    operator: "exact",
    value: "app.nuanu.com",
  },
  metrics: [{
    metricId: oneOfNineIdsInTELEMETRY_METRIC_IDSOrder,
    status: "AVAILABLE" | "NOT_INSTRUMENTED" | "UNAVAILABLE",
    events: [{ role: exactCodeOwnedRole, identifier: schemaBoundEventIdentifier }],

    exactPopulationSemanticsEvidenceDigest: lowercaseSha256OrNull,
  }],
  breakdowns: [{
    dimension: oneOfFiveIdsInTELEMETRY_DIMENSIONSOrder,
    status: "AVAILABLE" | "NOT_INSTRUMENTED",
    propertyIdentifier: schemaBoundBreakdownPropertyOrNull,
  }],
  exceptionFingerprint: {
    status: "PROVEN_OPAQUE" | "FIELD_NOT_PROVEN",
    propertyIdentifier: schemaBoundProviderFingerprintPropertyOrNull,
    officialSchemaEvidenceDigest: lowercaseSha256OrNull,
  },
  schemaFactsDigest: lowercaseSha256,

~~~

`metrics` contains exactly nine entries in the constant order, including every
`NOT_INSTRUMENTED` or `UNAVAILABLE` metric. An AVAILABLE entry has the exact role names, arity,
and order from `POSTHOG_QUERY_BUILDERS`, a non-null
`exactPopulationSemanticsEvidenceDigest`, and a value property only for p75.
A NOT_INSTRUMENTED entry has `events: []`, both nullable fields null, and no
manifest binding. In V1, schema-level UNAVAILABLE is valid only for a p75
metric whose exact primary event/value binding is proven but whose identical-
population total companion is not: it has the primary role/event and value
property, but a null population-semantics digest. It may be hashed as primary-
only evidence but can never be executed or added to approved hashes.
`breakdowns` similarly contains exactly five entries in
constant order; its nullable property is non-null exactly when AVAILABLE.
`hostScope.propertyIdentifier` is non-null exactly when AVAILABLE. The
exception fingerprint fields are both non-null exactly for `PROVEN_OPAQUE` and
both null for `FIELD_NOT_PROVEN`. One shared fail-closed scalar policy applies
to every provider identifier and public allowlist value: it rejects empty or
unbounded values, non-canonical or non-printable-ASCII values, controls, raw
URL/path/query payloads, email/phone/contact data (including phone-length digit
sequences embedded in text), token/secret markers, person/session/device
markers, and opaque scalar identifiers, including long unreviewed base-N-like
segments.

`schemaFactsDigest` is `digestJson` of all other schema-facts fields, including
the observation timestamp. `preflightId` is one newly injected UUID for this
baseline preflight, formatted as `napp-posthog-preflight-` plus one canonical
lowercase UUID v4, and binds the host scope, all nine metrics, all five
breakdowns, and the exception proof to one observation. The Task 2 read layer
requires the target project and `capabilityEvidenceDigest` to match the final
access-lock inventory, requires the inventory preflight ID to match, requires
`inventory.observedAt <= observation.observedAt <= now`, requires both ages no
greater than exactly 30 minutes, recomputes the digest, and requires the same `preflightId`

`authorizedPostProvider` is a host-owned macOS Keychain/CI-secret-store broker.
It resolves and injects the separately scoped `query:read` credential
internally; the credential value is never returned to the adapter. The
transport recomputes and requires exactly
`accessLock.host + accessLock.queryEndpointPath`, where the path is exactly
`/api/projects/{targetProjectResourceId}/query/`, and uses POST only. It
accepts no URL, path, project, credential, headers, or generic request from the
caller. The invitation browser session is never substituted for this broker.

This provider envelope is exact and closed. A non-200 status requires
`payload: null`; a 200 requires the exact payload and `redirected: false`.
Only the listed statuses are accepted. A payload has at most 1,000 coordinates;
`resultKind` must be `funnel` exactly for the three funnel builders and
`series` for every other primary/companion/auxiliary builder.
Each coordinate has zero to five sorted unique dimension IDs, exactly the same
number of dimension values, and exactly the code-owned series arity/order for
that request. A dimension value is a non-empty string of at most 128 UTF-8
bytes and exists only in memory until Task 1 normalizes it. Count and
unique-session values are non-negative safe integers; p75 is a finite
non-negative number. Every `bucketEndedAt` equals the exact canonical
`window.endAt`. Only the two envelopes issued inside one already validated
`postStructuredP75Pair` call may contain repeated full coordinate identities
`{queryId, queryHash, windowDigest, bucketEndedAt, dimensionIds,
dimensionValues}` without failing structural validation, so the p75 join layer
can classify pair ambiguity. Every non-p75 primary envelope and every
exception-fingerprint auxiliary envelope requires those full coordinate
identities to be unique; a duplicate is a malformed envelope. The validator
selects this policy from the code-owned transport method and immutable request
role before reading the payload; `queryId`, `resultKind`, or any response field
cannot opt a non-p75/auxiliary response into the p75 duplicate allowance.
Unknown keys, prototypes, symbols,
redirects, nested results, raw rows/events/persons/replay/export data, IDs,
URLs, or content/detail fields reject the entire response before candidate
emission.

A malformed HTTP-success envelope, unexpected status, redirect, oversized
payload, coordinate shape/type/bounds violation, or duplicate full coordinate
in a non-p75 primary or exception auxiliary envelope maps to the existing Task
1 limitation `HTTP_PROVIDER_BLOCKED`; it never invents a new limitation code. Statuses
401/403 map to `HTTP_AUTH_BLOCKED`, 429 to `HTTP_RATE_LIMIT_BLOCKED`, and the
listed 5xx statuses to `HTTP_PROVIDER_BLOCKED`. Raw success and error payloads
are normalized in memory and then discarded.

Task 2 tests this boundary with an injected synthetic provider only and make
no network or secret-store call. Compatibility between this bounded envelope
and a real approved PostHog connector/broker is `UNVERIFIED` until Task 4
freshly reads the live schema and connector response contract. A browser
session or invite acceptance does not establish production transport
compatibility.

Before the broker is called, the adapter rebuilds the query from code, validates
it recursively, computes its complete hash, and requires that hash in
`accessLock.approvedQueryHashes` for the exact approved window digest. The read
layer first validates schema-facts freshness/digest/same-preflight, exact
AVAILABLE binding membership, and access-lock approval; the builder validator
then checks only the structural binding/query/window relationship. For p75,
`postStructuredP75Pair` validates
both complete queries and the pair digest before the first of two exact-path
POSTs. It discards both responses if either call or pairing fails.

The p75 response normalizer joins one percentile aggregate to one total-count
aggregate by immutable metric ID, completed bucket, ordered dimension IDs, and
the exact in-memory breakdown coordinate. After both envelopes pass structural
validation, it indexes the full join key `{metricId, bucketEndedAt,
dimensionIds, dimensionValues}`. A duplicate full key in either bounded list,
or more than one count match for a percentile, is semantic pair ambiguity:
emit UNAVAILABLE with the retained primary hash, null pairing, no measured
payload, and `P75_COUNT_PAIR_AMBIGUOUS`. Missing/extra/mismatched keys use
`P75_COUNT_PAIR_MISMATCH`. These cases never become `HTTP_PROVIDER_BLOCKED`
and the adapter never joins by response order. The total result is the sole
`sampleSize`; result-array length, number of buckets, quantile response count,
and percentile metadata are forbidden substitutes. A 401, 403, 429, or 5xx
result becomes a stable BLOCKED limitation. Other missing/mismatched/ambiguous
count evidence makes the p75 metric UNAVAILABLE. All raw success/error
responses and in-memory coordinates are then discarded.

Non-p75 normalization follows the map rather than provider result shape:
`telemetry-freshness` uses its sole total as both count and `sampleSize`;
`route-health` and `js-exception-rate` use ordered series index 0 as the
denominator population and index 1 as the numerator; each funnel uses exact
first-step index 0 as `sampleSize` and exact last-step population as its
numerator. The adapter rejects a missing, reordered, duplicated, additional,
zero-denominator, or arity-incompatible series and never substitutes payload,
row, bucket, or array length. Before this normalization, it requires unique
full coordinates for every non-p75 primary and exception auxiliary envelope;
a duplicate produces BLOCKED / `HTTP_PROVIDER_BLOCKED`, emits no candidate,
and never becomes `P75_COUNT_PAIR_AMBIGUOUS`. If the duplicate is in the
exception auxiliary response, discard both that response and its already-read
primary response; do not fall back to `FIELD_NOT_PROVEN`. A future alternative
population definition requires a separately reviewed code-owned builder ID and
schema evidence; it cannot be injected through the manifest.

The candidate is a strict tagged union:

| Status | `queryHash` | p75 `p75Pairing` | measured payload |
| --- | --- | --- | --- |
| `AVAILABLE` | required | required for p75; `null` for non-p75 | required |
| `NOT_INSTRUMENTED` | `null` | `null` | absent |
| `UNAVAILABLE` | required | `null` | absent |
| pre-query `BLOCKED` with no complete query | `null` | `null` | absent |
| post-build/query `BLOCKED` | required | `null` | absent |

`queryHash: null` is therefore legal only for `NOT_INSTRUMENTED` or a
pre-query `BLOCKED` candidate for which no complete structured query existed.
Once a complete primary query existed, its hash is retained for every status,
including UNAVAILABLE response/pair failures and post-query BLOCKED results.

emitted by Task 2 as UNAVAILABLE with the completed percentile query hash and
`p75Pairing: null`. Task 1 rejects a candidate that contradicts this union; it
does not repair or reclassify it.

or breakdown. `publicValueAllowlists` is an exact plain object whose optional
keys are the five dimension IDs and whose present values are sorted, unique,
non-empty arrays of reviewed strings. A present dimension key selects
`public_value` mode: every value for that dimension must exactly match its
allowlist or normalization rejects the candidate. It never silently falls back
to random-ID mode. An omitted dimension key selects
`catalog_local_random_id` mode regardless of whether its value resembles a
public value elsewhere.

`napp-telemetry-bucket-` ID for repeats catalog-wide, and never returns the map
or raw value. Distinct values receive distinct IDs; a malformed UUID or
collision rejects the catalog rather than silently retrying. The map is
cleared in a `finally` block after normalized records have been constructed;
it is never
logged, persisted, included in a digest, or retained at module scope. A direct
normalizer caller must inject the same closure contract; it cannot inject a
finished ID or map.

## Telemetry Exit Gate

The PostHog lane is complete only when:

- pure normalization, structured-query builder, recursive guard, and exact
  transport tests pass using synthetic data;
- no credential appears in an argument, example, environment contract, log,
  artifact, command, or chat;
- exact host/project/path and every complete generated query hash are
  allowlisted and read back;
- every persisted p75 has an independently queried total-count companion over
  the identical event population, UTC window, exact app host, filters, and
  breakdown; both role hashes and the immutable metric/dimensions pair digest
  are approved before either request;
- each p75 sample size comes only from its exact one-to-one companion count;
  each emitted p75 `bucketEndedAt` equals the approved canonical `window.endAt`;
  duplicate full join keys or multiple valid matches are UNAVAILABLE /
  `P75_COUNT_PAIR_AMBIGUOUS`, missing/extra/mismatched full keys are UNAVAILABLE
  / `P75_COUNT_PAIR_MISMATCH`, unsupported evidence is UNAVAILABLE, n < 20 is
  SUPPRESSED, and none persists the percentile or selects a test;

  envelopes of a validated p75 pair call; a duplicate in any non-p75 primary or
  exception auxiliary envelope is `HTTP_PROVIDER_BLOCKED`, emits zero

- `HogQLQuery`, text query, raw rows/tables/columns, persons/replay, joins,
