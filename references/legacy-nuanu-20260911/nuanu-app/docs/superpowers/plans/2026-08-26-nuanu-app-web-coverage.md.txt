# Nuanu App Web/PWA Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expand the Nuanu App foundation into evidence-backed public,
authenticated-state, API, PWA, responsive, accessibility, and manual
iPhone/Android web coverage, then run the first safe baseline and file only
confirmed defects.

**Architecture:** Runtime-confirmed public surfaces become deterministic
Playwright contracts behind product-local page objects and a mutation guard.
Dynamic business claims remain UNVERIFIED until an approved oracle exists.
Graph validation and dry-run planning precede execution; candidate findings
become Bugs only after fresh-context reproduction, deduplication, regression
coverage, and Flow read-back. Optional privacy-normalized PostHog signals may
only add safe tests or triage priority; their status is reported separately and
never changes deterministic verdicts.

**Tech Stack:** TypeScript, Playwright, @axe-core/playwright, Node.js graph CLI,
Nuanu Flow control plane.

**Spec:** `docs/superpowers/specs/2026-08-26-nuanu-app-qa-project-design.md`

## Global Constraints

- Execute after the QA foundation plan. Execute Flow-dependent steps only
  after the Flow control-plane plan has created and verified NAPP.
- V1 covers `app.nuanu.com` web/PWA only. Physical iPhone/Android checks are
  manual evidence lanes; native apps are out of scope.
- Install the mutation guard before any public interaction. Do not click
  location permission, Call, Apple/Google provider handoff, reset delivery,
  consent mutation, booking, payment, profile mutation, or account deletion.
- Do not hard-code transient counts, hours, prices, rankings, or place
  availability as product truth.
- Test IDs are stable and begin `NAPP-`. Every case has PASS, FAIL,
  EXPECTED_FAIL, FLAKY, MANUAL, BLOCKED, UNVERIFIED, NOT_DEPLOYED, or
  INCONCLUSIVE status.
- A candidate bug is not a Flow item. Require clean-context reproduction,
  deterministic oracle, evidence, duplicate search, and action-time batch
  confirmation before external creation.
- WebKit/Chromium emulation never closes a physical-device case.
- Screenshots, traces, videos, console, and request evidence must be sanitized.
- Execute the standalone PostHog telemetry plan when approved access exists.
  If telemetry is BLOCKED, NOT_INSTRUMENTED, UNAVAILABLE, or SUPPRESSED,
  continue the deterministic safe campaign and report that status.
- Never consume raw analytics events, persons, replay, identifiers, exact URLs
  or query values, search text, exception details, headers, or bodies. Only the
  reviewed aggregate signal file may enter planning.
- Treat telemetry as BLOCKED unless the effective capability matrix is read
  back, one digest-bound schema preflight contains all nine metric statuses and
  is at most 30 minutes old, every metric has the fresh exact
  `app.nuanu.com` equality predicate,
  and a separate scoped host-secret transport or approved connector exists.
  A displayed role, `readOnly` flag, dedicated-project name, or invite browser
  session is not sufficient.
- Accept only recursively validated code-owned `TrendsQuery`/`FunnelsQuery`
  structures. `HogQLQuery`, text query, raw table/column/person/replay/event
  nodes, joins, and unknown fields select no tests.
- Require the explicit immutable canonical 24-hour UTC adapter window and its
  window-dependent approved hashes; never derive a telemetry window from the
  current clock. Accept production evidence only after the bounded connector
  envelope is read back; UNVERIFIED compatibility keeps telemetry BLOCKED.
- For non-p75 metrics, consume sample size only from the code-owned total,
  ordered rate denominator, or first funnel step. A response/row/bucket/array
  length is never a population.
- Consume p75 LCP/CLS/INP only with an independently queried total-count
  companion over the identical window, host, filters, and breakdown. Pair by
  immutable metric ID and dimensions, never result order/length or quantile
  shape; missing, mismatched, ambiguous, or unsupported count evidence makes
  only that p75 metric UNAVAILABLE.
- Consume only the standalone lane's exact catalog wrapper and tagged unions.
  Its standalone telemetry Task 2 owns raw coordinate joins; web tasks inspect
  structural normalized evidence only and continue when telemetry is unavailable.
- Consume exception groups only from the dedicated mutually exclusive
  fingerprint query with fresh provider-opacity proof; `FIELD_NOT_PROVEN`
  retains only aggregate exception evidence.
- Preserve shared dirty files; stage only owned paths.

The top-level keys, two `inventory` keys, `selectorEvidence` keys, and all 26
`selectors` keys are exact; unknown or missing keys fail closed. An AVAILABLE
selector has exactly `status`, `role`, `name`, `evidenceId`, and
`matchCount: 1`; an UNVERIFIED selector has exactly `status` and one
enumerated `reason`. Category and collection entries are typed
`{role,name,evidenceId,matchCount:1}` records, not strings. Names are
normalized non-empty accessible names of at most 200 characters, contain no
control characters or secret/token-like material, and every AVAILABLE
`(role,name)` and every `evidenceId` is unique in its scope. The
validator recursively rejects secret-like unknown keys and values, requires
all digests to be exactly 64 lowercase hex characters, and requires both times
to be canonical UTC ISO instants. No current name, taxonomy value, count,
class, slug, or query value is copied into tracked fixtures or test titles.

The root/probe `runtime-catalog.json` does **not** prove detail, auth, update,
marker, card, category, or collection selectors. It proves only the deployment
capture bound by the contract's top-level fields: `observedAt` must byte-equal
`runtime-catalog.json.capturedAt`, and `observationDigest` must byte-equal
`runtime-catalog.json.runtimeDigest`. Selector claims are independently bound
to a bounded reviewed observation.

`selector-capture-plan.v1.json` has exactly `schemaVersion`, `productId`,
`baseUrl`, `steps`, and `capturePlanDigest`; the first three values are
`1`, `nuanu-app`, and `https://app.nuanu.com`, and the final value is the
canonical SHA-256 of every preceding semantic field. It has at most 12 ordered
steps. An observe step is exactly
`{kind:"observe",state,postcondition:{role,name}}` for one enumerated state
(`root`, `places`, `map`, `place_detail`, `auth_entry`, `update_prompt`). An
activate step is exactly
`{kind:"activate",fromState,toState,purpose,target:{role,name},postcondition:{role,name}}`,
with both states enumerated, one reviewed exact accessible target, one reviewed
state-specific exact accessible postcondition for `toState`, and one purpose
from `open_places`, `open_map`, `open_profile_entry`, `open_place_detail`,
`close_place_detail`, or `show_on_map`. Every step for the same resulting state
must use a byte-identical postcondition, and the same `(role,name)`
postcondition cannot certify two different states. The postcondition is part
of `capturePlanDigest`; missing/unknown postcondition keys fail before browser
launch. At most eight activate steps are allowed. The private plan may contain
reviewed accessible names, but no current postcondition/target name is copied
to tracked code, fixtures, titles, or mappings. The plan cannot name Call,
reset delivery,
Apple/Google provider, location permission, consent mutation, booking,
payment, registration submission, profile mutation, or account deletion.
Unknown states, purposes, fields, repeated/cyclic transitions, or duplicate
role/name targets are rejected before browser launch.

The mutation-guarded producer observes only the states actually reached by
those reviewed transitions. Before navigation it installs the same bounded
request guard used by tests. After initial navigation and before attributing
any root records, it requires exactly one visible exact observe postcondition.
Before each activation it requires exactly one visible exact target; after the
activation it first requires the exact app origin and then exactly one visible
exact `toState` postcondition. Only after that ordered check may it create the
state entry or attribute accessible records to `toState`. Zero postcondition
matches records `STATE_NOT_OBSERVED`; two or more record explicit
`AMBIGUOUS_ROLE_NAME` evidence. Either outcome leaves the state and all of its
selectors/inventory UNVERIFIED, with no state-bound candidate records. It
never types, submits, grants permission, clicks a prohibited control, follows
provider/Call handoffs, reads input values, or uses CSS/text/ordinal fallback.

`runtime-selector-observation.v1.json` has exactly `schemaVersion`,
`productId`, `baseUrl`, `observedAt`, `runtimeDigest`, `capturePlanDigest`,
`states`, `ambiguities`, `mutationLedger`, `limitations`, and
`observationDigest`. It is capped at six verified states, 64 total accessible
match records across `states` and `ambiguities`, 25 blocked mutation records,
and 64 KiB serialized size. `states` is a sorted unique list of exact
`{state,postcondition,records}` objects. `postcondition` is exact
`{role,name,evidenceId,matchCount:1}`: its role/name projection must
byte-equal the reviewed plan value and its evidence ID must reference the
same singleton in that state's `records`. Each
`records` member is a sorted unique
`{evidenceId,state,role,name,matchCount}` record; its nested `state` must equal
the owner and `matchCount` is the exact integer returned for that exact
role/name locator, bounded to `1..65535`. One record represents one unique
`(state,role,name)` tuple; duplicate DOM matches increase `matchCount` and are
never collapsed into a certifiable singleton. `evidenceId` is the canonical
SHA-256 of exact `{state,role,name,matchCount}`, so changing only the count
changes both evidence identity and the enclosing observation digest.

`ambiguities` is a sorted unique list of exact
`{evidenceId,attemptedState,role,name,matchCount}` records with
`matchCount` in `2..65535`. It captures duplicate accessible matches,
including a duplicate state postcondition when no state entry may be written;
it is evidence only and cannot be referenced by selectors, inventory, or
bindings. Every state record with `matchCount > 1` has a byte-consistent
ambiguity record, and every ambiguity has a matching exact
`AMBIGUOUS_ROLE_NAME` limitation. If any exact count exceeds 65535 or the
record/file cap, the producer fails closed with the attempted capture
UNVERIFIED and creates no promotable candidate; it never truncates a count to
the bound.

`mutationLedger` is exactly
`{records:[{method,originAndPath}],overflowed}`. `limitations` is a sorted
unique list of exact records. Non-ambiguity variants are exactly
`{state,reason}` with `ACCESSIBLE_ROLE_NAME_UNAVAILABLE`,
`STATE_NOT_OBSERVED`, or `PROHIBITED_INTERACTION_REQUIRED`; the ambiguity
variant is exactly
`{state,reason:"AMBIGUOUS_ROLE_NAME",evidenceId,matchCount}` and must reference
the byte-consistent ambiguity record. Unknown nested keys fail validation.
`observationDigest` is the canonical SHA-256 of every preceding semantic
field, including every postcondition, match count, ambiguity, and time.
Evidence IDs are observation identities, not DOM IDs. Evidence contains no
generic DOM text,
classes/IDs, query/fragment, URL values beyond origin+pathname, request/response
headers or bodies, cookies/storage/input values, coordinates, screenshots,
traces, or video.

After independent review, `selector-bindings.v1.json` has exactly
`schemaVersion`, `productId`, `baseUrl`, `observationDigest`,
`capturePlanDigest`, `selectors`, `inventory`, and `bindingDigest`.
`bindingDigest` is the canonical SHA-256 of every preceding semantic field.
Its `selectors` object has all and only the 26 selector keys, each mapped
either to exact `{status:"AVAILABLE",evidenceId,matchCount:1}` or exact
`{status:"UNVERIFIED",reason}` with an enumerated RuntimeSelector reason. Its
`inventory` has exactly `categories` and `collections`, each a sorted unique
list of exact `{evidenceId,matchCount:1}` records whose referenced verified
state records carry the item role, accessible name, and exact count one; each
list is capped at 50 and the bindings file at 64 KiB. Unknown keys,
unreferenced/ambiguous IDs, any count other than one, or an
observation/capture-plan digest mismatch fails validation. The offline
`contract-candidate` command resolves
those references, computes `bindingDigest`, and writes the closed candidate.
It never infers by name or array order. Promotion to
`runtime-contract.v1.json` is a separate reviewed private-file action, not an
automatic command.

The loader accepts no path and derives the contract, runtime catalog, selector
observation, capture plan, and bindings from those fixed paths. A selector
contract is READY only when:

- the top-level time/digest match the current runtime catalog exactly;
- `selectorEvidence.observedAt` equals the selector observation's
  `observedAt`; its other three fields match the separately recomputed
  observation, capture-plan, and binding digests exactly;
- the selector observation's `runtimeDigest` equals the current catalog's
  semantic `runtimeDigest` and is no more than 30 minutes old;
- every AVAILABLE selector/inventory record resolves from a verified state,
  has `matchCount: 1`, and byte-equals its referenced observation entry; no
  ambiguity evidence is promotable;
- every verified state's recorded postcondition role/name byte-equals its
  reviewed plan postcondition, references a same-state record with
  `matchCount: 1`, and was observed before the remaining state records were
  attributed.

`nuanu-app:graph validate` owns the same durable attestation before writing
`graph.json`, and the Playwright loader repeats it at execution time. Missing
contract/evidence is BLOCKED; malformed fields, stale/mismatched evidence,
missing selector, or digest/time mismatch is UNVERIFIED. A valid selector slot
with `status: "UNVERIFIED"` marks only dependent cases UNVERIFIED. If canvas,
marker, or card behavior has no accessible role/name, the reviewer records
that state and opens a reviewed accessibility/schema amendment; the page
object never falls back to CSS, classes, text scanning, ordinal selection,
`.first()`, or a role union.

## Task 1B Semantic-Settle Amendment — Bounded Root Capture

This amendment is approved only to replace the empty-root-candidate capture
mechanic. It does not authorize a live capture, selector observation, contract
promotion, mapping update, graph build, dry run, or Playwright campaign. A
fresh independent review must pass before the first runtime command that uses
the changed observer.

### Closed behavior and catalog schema

`networkidle`, fixed sleeps, `waitForTimeout`, selector racing, source names,
raw DOM/text, and direct query/fragment retention are prohibited in the
semantic-settle reducer.

Let `t0` be the injected monotonic-clock reading immediately after the initial
same-origin `domcontentloaded` check and successful first candidate sample.
Take sample zero at `t0`, then request each later sample from the injected
absolute-deadline scheduler at `t0 + n * 250 ms` for `n = 1..19`. A sample
must complete before the hard `t0 + 5000 ms` deadline; it may not start at or
after that deadline. The scheduler may be a production timer adapter, but
production code must not call a fixed Playwright sleep. A snapshot collection
that cannot finish before its absolute deadline is terminal and writes no
catalog.

**Session/collector boundary (normative):** `async function observePublicRuntimeSession({ context, rootUrl, now,
clock, scheduler })` is the only BrowserContext→Page lifecycle owner. It
creates the Page, installs all Page/context guards and listeners before
navigation, performs the root navigation, origin checks, settle orchestration,
manifest request/check, fixed probe, and shutdown checks, then releases the
Page. The Page never escapes that function: it is neither returned, placed in
an object/array, retained in a callback result, nor passed anywhere except the
direct call `publicSnapshot(page)` and a private zero-argument collector closure
used only during that session. `publicSnapshot(page)` is the sole raw DOM/CSS
extraction boundary; it returns only a bounded sanitized snapshot plus
metadata/overflow flags. It may use the fixed structural `locator("html")`
evaluation and only the reviewed DOM mechanics needed to derive the closed
native/ARIA role set and permitted accessible-name sources (`aria-label`,
associated label, non-secret `title`, and button/link text): `document.title`,
`document.querySelector`, `document.querySelectorAll`,
`document.getElementById`, `globalThis.CSS.escape`, `tagName`, `labels`,
`children`, `isContentEditable`, `hasAttribute`, `getAttribute`,
`querySelector`, and `textContent`. It cannot emit selectors, IDs, classes,
generic DOM text, source names, or raw DOM objects. No code outside
`publicSnapshot` may read, call, alias, destructure, return, pass, or
computed-access DOM globals (`document`, `window`, `globalThis`) or their
derivatives. No code outside `observePublicRuntimeSession` may operate on a
BrowserContext or Page lifecycle; `publicSnapshot` may use only its passed Page
for the reviewed extraction. The reducer receives neither a Page, BrowserContext,
DOM node, locator, CSS selector, nor source text.

The session returns this data-only result, and no Page, BrowserContext,
Browser, locator, callback, or raw DOM value may occur in it:

```ts
type RuntimeObservationSessionResult = Readonly<{
  root: Readonly<{
    projection: AccessibleCandidateSnapshot;
    settle: RuntimeSettle;
    metadata: RuntimeMetadata;
  }>;
  manifest: RuntimePwa;
  probe: Readonly<{ route: "/__napp_runtime_probe__"; status: number }>;
  requestEvidence: Readonly<{ apiHosts: readonly string[]; dependencies: readonly string[] }>;
  overflow: Readonly<{ candidateRecords: boolean; snapshotBytes: boolean }>;
}>;
```

Any true overflow is terminal and produces no runtime catalog. The outer
`observePublicRuntime` may only launch/close the Browser, create the Context,
call this session, and normalize its data-only result. Production passes the
private zero-argument collector closure and installed guard check to
`settleRootCandidateSnapshots({ clock, scheduler, collectSnapshot,
assertBoundary })`; tests inject a fake collector instead.

Each snapshot is the canonical UTF-8 JSON bytes of the already-normalized,
sorted, deduplicated projection with exactly these keys in this order:

```ts
type AccessibleCandidateSnapshot = Readonly<{
  surfaces: readonly RuntimeRoleName[];
  controls: readonly RuntimeRoleName[];
  taxonomy: readonly string[];
}>;
```

It has at most 64 total candidate records and at most 16,384 serialized bytes.
The observer compares the canonical bytes, not object identity, locator state,
or a semantic approximation. It retains no historical snapshots. The selected
stable projection is written once as the existing `rootCandidates` values; the
only additional durable record is exactly:

```ts
type RuntimeSettle = Readonly<{
  status: 'STABLE_NONEMPTY' | 'STABLE_EMPTY' | 'LATE_HYDRATION' | 'NEVER_SETTLES';
  sampleCount: number; // integer 2..20
  initialSnapshotEmpty: boolean;
  candidateSnapshotDigest: string | null; // SHA-256 of selected canonical bytes
}>;
```

`runtime-catalog.json` has an exact new top-level `settle` key. Its validator,
normalizer, `RuntimeCatalog` declaration, canonical catalog reconstruction,
and `runtimeDigest` all include the record. `capturedAt` remains non-semantic;
`settle.status`, `sampleCount`, `initialSnapshotEmpty`, the selected
projection, and `candidateSnapshotDigest` are semantic. A `null` digest is
valid only for `NEVER_SETTLES`; every other status requires one lower-case
64-hex digest equal to the selected projection's canonical-byte hash.
`initialSnapshotEmpty` always reports whether sample zero was empty. It is
false for `STABLE_NONEMPTY`, true for `LATE_HYDRATION`, and either truthful
value for `STABLE_EMPTY` and `NEVER_SETTLES`; nonempty → empty → empty is
therefore `STABLE_EMPTY` with `initialSnapshotEmpty: false`. `sampleCount`
counts completed snapshots, including both members of the stable pair.

The result table is exact:

| Condition | `settle.status` | Persisted root candidates | Planning consequence |
| --- | --- | --- | --- |
| First equal adjacent pair is nonempty and sample zero is nonempty | `STABLE_NONEMPTY` | second pair snapshot | may be reviewed as a root candidate input; never self-promoted |
| First equal adjacent pair is empty | `STABLE_EMPTY` | closed empty projection | candidate-dependent cases `UNVERIFIED`; no selector plan execution |
| Sample zero is empty, a later sample is nonempty, then the first equal adjacent nonempty pair occurs | `LATE_HYDRATION` | second nonempty pair snapshot | may be independently reviewed; it is not a hydration PASS |
| No byte-identical adjacent pair by the deadline | `NEVER_SETTLES` | closed empty projection | candidate-dependent cases `UNVERIFIED`; no selector plan execution |

If an empty sample later changes, it is not stable empty. If a nonempty sample
later changes, it is not stable nonempty. In both cases the observer continues
only on its absolute schedule until it finds the required pair or reaches the

## Coverage Exit Gate

The web/PWA campaign is complete only when:

- every live Playwright command has its own freshly reviewed
  runtime→contract-rebind→validate→dry-run-plan evidence immediately before
  execution;
- graph validation attests the fixed private runtime contract against the
  exact sibling catalog time/digest **and** separately attests the bounded
  selector observation, reviewed capture plan, typed bindings/inventory, and
  every referenced evidence ID/count; every promoted reference has exact
  `matchCount: 1`, every recorded state passed its unique reviewed
  postcondition before attribution, and ambiguity evidence selects nothing;
  no root/probe record substitutes for that selector evidence, and no guessed
  selector/digest repair or CSS/text/ordinal fallback occurred;
- missing contract/auth prerequisites remain BLOCKED while malformed,
  missing/duplicate/inaccessible selectors and digest drift remain UNVERIFIED;
- the durable evidence run was created only by the fixed module-derived
  run-context writer, and offline synthetic cases are excluded from live
  coverage/pass counts;
- every live case attaches a capped sanitized mutation ledger in `finally`,
  and every first-party 5xx follows the three-context product/environment
  triage rule before defect classification;
- every implemented test has a stable ID and explicit status;
- public functional/API/PWA/responsive/a11y/auth-boundary results have
  sanitized evidence;
- dynamic business/performance/visual claims remain UNVERIFIED until approved;
- optional telemetry status and privacy suppressions are explicit; telemetry
  BLOCKED does not block completion of the deterministic safe campaign;
- telemetry only adds safe test selection and never supplies PASS/FAIL,
  deployment proof, or automatic Bugs creation;
- no telemetry query runs without complete capability read-back, the exact app
  host predicate, fresh all-nine-status schema preflight, immutable approved
  24-hour UTC window, recursively valid code-owned structured shape/hash,
  verified bounded provider envelope, and a separate scoped transport; missing
  or UNVERIFIED proof leaves only telemetry BLOCKED;
- no unkeyed cohort hash is claimed as privacy and exception grouping follows
  the dedicated-query official-opaque-proof plus 20-observation rule;
- every persisted p75 has a one-to-one independently counted same-window/
  scope/filter/breakdown cohort with count at least 20; absent or ambiguous
  count evidence remains UNAVAILABLE/SUPPRESSED and never selects tests;
- optional telemetry uses the exact catalog wrapper/digest, locked query-hash/
  pairing unions, strict public-allowlist mode, and one mapless catalog-wide
  random-ID memo; downstream web tasks never re-interpret raw provider rows;
- every non-p75 telemetry sample uses its code-owned total, denominator, or
  first-step origin; response/row/bucket/array length is never sample size;
- every physical-device case remains MANUAL/BLOCKED without human evidence;
- every confirmed bug has dedupe, regression coverage, Flow read-back, and
  exact `NAPP-*` identifier;
- no prohibited browser or upstream action occurred.
