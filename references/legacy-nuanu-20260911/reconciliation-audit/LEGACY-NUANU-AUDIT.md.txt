# Legacy Nuanu source reconciliation — Lead AQA audit

Date: 2026-09-11. Scope: read-only source/history and preservation review of four previously omitted NuanuFlowQA branches. This is **not functional qualification**, a product campaign, installation approval, or a complete line-by-line correctness review. No product, browser, test suite, credentials, tracker, worker, process, deployment, or source mutation was used. The only reviewer-written file is this report.

## Decision

Preserve the selected source as private, inert, attributed historical material, with committed snapshots, dirty overlays and deletion records kept distinct. Do not activate any branch as the current universal runner. There is useful unique work here; treating all four branches as already represented by Starter/Freeland would be incorrect. Conversely, their presence does not justify a second runtime owner, proof gate, MCP transport or tracker outbox in the current assembly.

Before shipping the archive, preserve the applicable donor license notices and explicitly label historical operational metadata. The original proposed `no ... private captures` wording is too broad: source fixtures and plans contain historical real platform identifiers. No credential payload was identified in the scoped inspection; this is not proof of public-release sanitization.

## Capabilities, overlap and unique value

### Universal QAH and PayDemo

Critical inspected paths: `scripts/qah/contracts.mjs`, `graph-plan.mjs`, `environment.mjs`, `release-policy.mjs`, `worker-contract.mjs`, `install-preflight.mjs`, `onyx-browser-probe.mjs`; package scripts; process graph and live-column-start fixture; proof-gate operations runbook and canary design.

- A distinct closed four-branch engine (`code/api/ui/domain`) separates applicability, product result, environment status, evidence status and declared outcome codes. PASS requires verified evidence; release classification distinguishes product failure from neutral hold.
- Graph-plan receipts bind ticket/candidate/environment, graph/knowledge digests, freshness, required checks and criticality. This is not the current Kernel campaign/receipt schema and has no demonstrated adapter into it.
- Environment ownership uses run/attempt/environment fencing and scoped managed-command lifecycles. PayDemo provides controlled broken/fixed variants and deterministic execution/broker/provenance examples. It is a QA fixture product, not real-payment acceptance.
- Native integration includes immutable ArtifactVersion readback, same-task three-phase materialization, server-owned verified-commit publication and stock `qa_result_v1` routing. Historical multi-task artifact custody failed and the runbook replaces it with a single-task design. These are valuable platform compatibility lessons, not current live success claims.
- Worker adapter validation is hard-pinned to version `0.3.14` and SHA-256 `9105a1b134fdd74b7aa5454aa4f622522939d683c413e83925ddbe3cadab4a41`. Install preflight hard-pins the NuanuFlowQA repository origin, policy digest and requested decision model. The Onyx probe additionally pins a specific public origin and uses a persistent CDP context. These dependencies prevent blind portable activation.

Current Kernel/Console already own registration, knowledge/graph revision, approved plans, bound receipts, reconciliation, fixtures, interruption handling and attributed reviews. QAH therefore overlaps in concepts, **not interchangeable implementation or evidence**. Its distinctive future-reference value is the native Flow proof-gate/worker boundary plus controlled PayDemo/environment custody. Reuse requires a bounded adapter/contract decision and tests; do not copy its release decisions into current accepted receipts or create another process controller.

### Nuanu App foundation

Critical inspected paths: `tools/nuanu-app-graph/{model,source,cli,runtime,runtime-contract,posthog-query-builders,posthog-read,telemetry-policy,flow-outbox}.mjs`, browser evidence/safety fixtures, synthetic PostHog fixture and product README. Its fixed product namespace is `nuanu-app`, runtime origin `https://app.nuanu.com`, and CLI source origin/root `https://github.com/nuanu-ai/nuanu-web.git` / `apps/nuanu-web`.

- Source-aware and runtime-only graph planning remain distinct; source lock does not attest deployed SHA. Private graph writes use attestation/commit-marker custody and explicit refresh semantics.
- The documented nine-case foundation is narrow read-only web/PWA coverage, not authenticated, native-app or physical-device acceptance. Browser guard and bounded sanitized observation patterns are useful, but a per-test fixture is not a universal network policy.
- Aggregate-only PostHog query construction, least-privilege access lock, exact query/window/schema identities, cohort/sample constraints and telemetry-to-graph signals are substantial unique source. The inspected access-lock fixture is explicitly synthetic (`posthog.synthetic.invalid`), not a real credential/access grant. No current generic analytics adapter or compatibility with current managed graph contracts was demonstrated.
- Committed Flow outbox code validates confirmed findings and closed delivery actions. The working overlay replaces lock-centric authority with an append/replay journal, fences/leases, durability handling and snapshots. This is a major state-machine change, not a small doc update.

Tracked overlay: **5,617 insertions / 646 deletions across 10 files**. In addition, the untracked `tests/nuanu-app-graph/semantic-settle.test.mjs` has **2,434 lines**. No result from HEAD can be reattributed to these working bytes. Preserve the complete overlay together with its base SHA, but do not cherry-pick isolated contract or outbox files: their interfaces and tests move together.

Highest-value future extraction candidates: aggregate analytics privacy contracts; semantic-settle classification; unknown-outcome/durable publication negative controls. Each must be reviewed against the existing owner, not adopted as an extra universal outbox/graph system.

## Preservation allowlist, privacy and dependency boundaries

Reviewed one-off script: `../preserve-legacy-nuanu.mjs` relative to the integration directory's parent. It selects exact committed blobs plus separately named working overlays, hashes/readbacks copied bytes, refuses existing destination overwrite, rejects dirty symlink/non-file entries and records deletions. `.txt` suffixes avoid ordinary automatic JS/test/package/skill discovery; they do not make embedded instructions authoritative or guarantee no user could execute them manually.

The original positive allowlist excludes `.env`, storage state, private `docs/local`, credentials, generated test evidence, binaries, node_modules and external/TECT trees. It does **not** prove an executable dependency closure: common root config/helpers may remain outside the selection, and pinned external worker package bytes are not included. Preserve package/lock files as inert dependency provenance, not permission for `npm install` or an assurance that dependencies are safe/current.

Original touched-path exclusions are fully accounted for:

- QAH: root `README.md`; Freeland source-access plan and six implementation/test paths already in the separate bootstrap audit.
- Nuanu App: `.env.example`.
- Flow E2E: `.env.example`, root `README.md`, `CLAUDE.md`, `.claude/skills/qa-check/SKILL.md`, `.github/workflows/e2e.yml`.
- Acceptance boundary: root `README.md`, `playwright.config.ts` (the latter adds the always-enabled `program` test project).

Root READMEs, Flow E2E workflow/entrypoint history and acceptance test configuration can be preserved as inert attributed source to improve future comprehension; otherwise these omissions must stay explicit. Never install the historical skill or activate the scheduled workflow. The workflow contains variable/secret references, not inspected secret values; it remains an old mixed-product CI design.

Privacy review combined all selected committed source with path/line-only scans for personal paths, UUIDs, email addresses, literal-secret-like assignments, embedded images and third-party notices; critical flagged material was inspected. Most test identifiers/secret-like strings inspected are synthetic negative controls. Important real historical metadata remains:

- `tests/qah/fixtures/live-column-start.json` contains actual historical generated graph/binding/project/state identifiers.
- `docs/operations/universal-qa-proof-gate-runbook.md` and the stock single-task design reference a real failed run and its failure history.
- `docs/superpowers/plans/2026-08-10-paydemo-native-assist-boundary.md` contains historical project/binding/template/agent/run identities and mutation instructions.
- Nuanu Flow sandbox source and plans contain exact historical workspace/project IDs; the QAH adaptation plan includes machine-local paths.

These are private operational metadata, even without authentication secrets. Preserve only in the authorized private archive with explicit historical/inactive labels. Public redistribution would require a separate content/privacy review. Do not claim that a limited regex scan proves absence of all secrets, personal data, private URLs or licensing obligations. No binary captures, raw analytics provider data, audio, sessions or external product source were selected in the reviewed allowlist. Dirty content is recorded as captured working bytes, not an atomic consistent runtime snapshot.
